## Reading the specs

- `docs/DESIGN.md`: product surfaces mapped to the design kit, cited in specs as "DESIGN §n" (floating surfaces: picker, HUD, bubble, launcher; flat workspace: editor, library, settings). UI work must follow a named surface here. `specs/design-implementation.md` tracks kit traceability and open design decisions.
- `specs/i18n-plan.md` (UI languages: approach, phases, decisions, what was built), `specs/caption-editor-plan.md` (the R3c caption editor), `locales/README.md` (how to add a string or a language)
- `docs/SPIKES.md`: feasibility spike results (S1–S6, macOS filled in, Windows pending); a spike passes only if it passes on both Windows and macOS
- `specs/features/NN-*.md`: per-feature behavior and acceptance criteria to build and test against

Spec rules:
- When two documents disagree, raise it; don't guess.
- IDs (`AREA-n`, acceptance criteria `AREA-n.ACm`) are stable. Never renumber; mark retired ones *Withdrawn*. Cite AC IDs in tests and commits.
- The specs are exported from a claude.ai doc, so edit the markdown here and keep the format of the feature template in `specs/README.md`.
- Units: logical px unless marked physical; times in `MediaTime` ticks (120,000/s); MB = 10^6 bytes.

## Architecture (big picture)

- **One action bus.** Four clients (desktop app, overlay windows, CLI, MCP server) talk only to `cm-daemon`; clients never call engine crates directly. GUI, CLI and agents therefore share state, undo and confirmation gates.
- **Headless crates.** Everything under `crates/` must be testable without a display (planned set: `cm-core`, `cm-capture`, `cm-camera`, `cm-audio`, `cm-cursor`, `cm-encode`, `cm-media`, `cm-render`, `cm-ai`, `cm-auth`, `cm-storage`, `cm-publish`, `cm-jobs`, `cm-library`, `cm-daemon`, `cm-mcp`, `cm-cli`, plus `cm-ipc` and `cm-i18n` (the `.po` loader and formatting, no dependencies); existing today: all of them; `cm-publish` has the YouTube provider only). Hardware paths sit behind traits with scripted fakes. `apps/desktop` and `apps/overlay` are thin shells.
- **Bundles are the source of truth.** A capture is a folder (`.cmrec` / `.cmshot`) with media tracks plus `manifest.json`; SQLite only indexes them. Masters are read-only after recording; trims, cuts, speed, layout and zooms live in `manifest.edits`. Every change is a revision tagged `user` or `agent:<name>`, which backs undo.
- **Recording.** Each source (screen, camera, mic, system audio, cursor) is its own track, stamped with OS capture time and converted to `MediaTime` on one session clock. In-process hardware encoders write 2 s fragmented MP4 (crash loses at most one fragment). FFmpeg is only used after recording, for export (the interim `quick` exporter in `cm-media`). The webcam bubble window is excluded from screen capture and composited at export, which keeps it editable. `RecordingSession` (in `cm-daemon`) owns the clock and the tracks; the clock origin is taken before any track starts, pause removes the gap from every media file's time (the cursor log stays in session time), and `recording.lock` in the bundle marks an unfinished recording for startup recovery.
- **Export.** One `wgpu` compositor drives both editor preview and export, and runs headless for CLI/agents.
- **Jobs.** Export, transcribe, upload and publish are persisted SQLite jobs with resumable state, retries and progress events on the bus.
- **Providers.** `StorageProvider` and `PublishProvider` traits keep integrations swappable.
- **Secrets.** OAuth (PKCE + loopback redirect, system browser) and API keys are stored via `keyring`; config holds only key names. Users bring their own platform credentials in v0.1.
- **Agent tiers.** Free actions run immediately; Confirm (start recording, the 60 fps self-test, publish, delete, discard or restart a take) needs an on-screen confirmation with a 5 min timeout and the dialog shows exactly the plan that runs; `set_settings` cannot write app-only keys (library, privacy, shortcuts, permissions, agents, storage, export, mcp, auth); Never (reading tokens, changing remote privacy, disabling the recording indicator) is not exposed. Mutating tools take an optional `request_id` for idempotency, and each tool has the same name as its CLI subcommand (`capture_screenshot` ↔ `capturemann capture screenshot`).

## Commands

- Build and check (what CI runs on macOS and Windows): `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`. Add `-p <crate>` to scope. CI also installs FFmpeg so the export tests run instead of printing SKIPPED. License and advisory check: `cargo deny check` (`deny.toml`; 7 documented `unmaintained` ignores, all transitive via `gpui`, and an `Unlicense` exception for `whisper-rs` and `whisper-rs-sys` only). **`cm-ai` builds whisper.cpp from source (`whisper-rs`), so building the workspace needs `cmake` and a C++ toolchain** (`brew install cmake`; the GitHub macOS and Windows runners have it, not yet observed in CI). Real-model check (never downloads): `CM_WHISPER_MODEL=<ggml file> CM_WHISPER_AUDIO=<speech file> [CM_WHISPER_REFERENCE=<text>] cargo test -p cm-ai --test real_model -- --ignored --nocapture`.
- Hardware tests are `#[ignore]` (33 of them) and print `SKIPPED` without permission; run them one at a time, for example `cargo test -p cm-capture --test record_real -- --ignored --nocapture --test-threads=1`. They record your screen, camera or microphone: run them only when the user asks, keep them short, and delete the output.
- Manual scripts in `tests/manual/`: `ANN-2.md`, `CAP-1.md`, `CAP-1-overlay.md`, `REC-1.md`, `REC-5.md`, `REC-7.md`, `CAM-1.md`, `CAM-2.md`, `AUD-1.md`, `EXP-1.md`, `PRM-1.md` (steps, privacy notes, pass criteria), `I18N-IME.md` (Telex and VNI typing), `CAP-EDIT.md` (the caption editor), and the M4 set `M4-GATE.md` (the checklist and the setup), `PLAY-1.md`, `EDT-1.md` to `EDT-5.md`, `CAM-3.md`, `EXP-2.md`; the publishing ones `PUB-1.md` (YouTube setup from scratch) and `PUB-2.md` (publish with every field). Reports of manual runs go in `verification/` (template in its README); say "verified" only with one.
- Synthetic recording for edit, export and playback runs (no screen, camera or microphone): `cargo run -p cm-daemon --example make_fixture -- --library <dir>` (screen frame counter with flash, mic beep, camera, system tone, a pause, cursor path; `--secs`, `--no-pause`, `--no-camera`, ...; the library is never your real one). The M4 gate test: `cargo test -p cm-desktop --test parity -- --nocapture` (needs FFmpeg and a GPU, else SKIPPED); `-- --ignored` adds the bubble-layout check that fails until CAM-3 makes the preview draw the stored layout; `CM_PARITY_KEEP=<dir>` keeps the exports and compared frames.
- End-to-end recording check on this Mac: `cargo run -p cm-daemon --example record_e2e -- --tracks screen,cursor --secs 10` (add `mic,camera,system`, `--pause-at`, `--kill9-test`; it never prompts for permission).
- UI strings: `cargo run -p cm-i18n -- check` (catalogue consistency), `-- extract` (regenerate `locales/capturemann.pot` after adding strings), `-- unwrapped` (list UI literals not yet wrapped), `-- baseline`, `-- coverage` (per-language percentages); `CAPTUREMANN_PSEUDO_LOCALE=1 cargo run -p cm-desktop` shows the accented, 30 % longer pseudo-locale for layout checks; `LAYOUT_WIDTH_REPORT=<file> cargo test -p cm-desktop --lib layout_width_tests` writes the width table.
- Spikes (separate workspace, reference only): `cargo run --manifest-path spikes/Cargo.toml -p spike-shot`.
- Binaries: `capturemann` (`cm-cli`), `cm-mcp` (the MCP server, stdio or `--http`; `capturemann mcp` launches it), `cm-daemon` (headless daemon, same library and settings as the app), `cm-desktop`, `cm-overlay`.
- Environment: `CAPTUREMANN_SOCKET`, `CAPTUREMANN_LIBRARY`, `CAPTUREMANN_CONFIG_DIR` (point a second instance at its own data), `CM_FFMPEG` (FFmpeg path), `CM_ALLOW_INPUT_INJECTION=1` (REC-7 injection test).
- `make bundle` (macOS) runs `packaging/macos/bundle.sh`: release build of `cm-desktop`, `cm-overlay`, `capturemann`, `cm-mcp`, assembled in a temp folder, signed with `CaptureMann.entitlements`, verified and swapped in atomically as `target/bundle/CaptureMann.app` (bundle id `dev.capturemann.app`), with LICENSE, NOTICE and THIRD_PARTY_LICENSES in `Contents/Resources`. `make run-bundle` also opens it. `make licenses` regenerates `THIRD_PARTY_LICENSES.md` (regenerate when `Cargo.lock` changes). Flags: `CM_BUNDLE_OUT` (output folder, for tests), `CM_FFMPEG_BUNDLE` (bundle and sign an LGPL FFmpeg; GPL builds are refused; without it `packaging/ffmpeg/out` is bundled when `make ffmpeg` has built it), `CM_NO_FFMPEG=1` (no FFmpeg), `make bundle-release` (fails unless the LGPL FFmpeg and its licence files are bundled), `CM_HARDENED=1`, `CM_SIGN_IDENTITY`, `CM_SKIP_BUILD=1`, `CM_BUNDLE_ID`, `CM_BUILD_NUMBER`. Use the bundle, not `target/release/cm-desktop`, whenever macOS permissions matter.
- `make ffmpeg` (macOS arm64) builds the LGPL FFmpeg that ships in the app: `packaging/ffmpeg/build-macos.sh` downloads pinned official source tarballs (FFmpeg, libvpx, libopus; SHA-256 checked), builds them statically with only the components the product calls, self-checks the licence, the components and the linked libraries, and writes `packaging/ffmpeg/out/{ffmpeg,ffprobe,BUILD-INFO.txt,SOURCE-OFFER.txt,LICENSES/}` (ignored by version control; see `packaging/ffmpeg/README.md`). `packaging/ffmpeg/with-bundled-ffmpeg.sh <command>` runs a command (for example `cargo test --workspace --locked --no-fail-fast`, which passed with 1,933 tests on Oct 23, 2026) with every product call done by that build; test fixtures, the parity test's frame extraction and decoding an exported WebM still use the `ffmpeg` on `PATH` (the shipped build has no libx264, no `lavfi`, no `select` filter and no VP9 or Opus decoder, because the product never needs them) and the script prints how many calls each binary served. When a feature needs another FFmpeg component, add it to the lists at the top of `build-macos.sh`. `cm-media` finds FFmpeg in the order `CM_FFMPEG`, next to the executable (the bundled copy), `PATH`.
- **Signing-identity workflow (macOS).** Ad-hoc builds get a new signature each time and macOS drops the Screen Recording grant. Once, run `packaging/macos/create-dev-identity.sh` (the user runs it; it asks before changing the keychain); after that `make bundle` finds "CaptureMann Local Dev" by itself and the grant survives rebuilds. Use `tccutil reset` only when a grant is stale, and never against the bundle id of the user's daily copy. A grant made while the app was signed ad hoc keeps an old code requirement: macOS then logs `Failed to match existing code requirement` (see `/usr/bin/log show --predicate 'subsystem == "com.apple.TCC"'`) and the permission stays "not granted" even though the switch is on; the user removes the entry with the minus button in System Settings and grants it again (Input Monitoring hit this on Oct 24, 2026). Never run `create-dev-identity.sh` or `make bundle` over `target/bundle` unless the user asks (their app may be running from it). Details: `packaging/macos/README.md`.

## Constraints to respect

- **No GPL/AGPL code in shipped binaries** (Apache-2.0): LGPL FFmpeg only (built by `make ffmpeg`, bundled by `make bundle`; `bundle.sh` refuses a GPL, nonfree or libx264 build), native hardware encoders only (no software H.264 encoder ships: the OpenH264 fallback was removed on Oct 24, 2026 to avoid the H.264 patent exposure of a source build; Macs without a hardware H.264 encoder, before about 2016, are not supported in v0.1). CI runs `cargo deny`. The interim exporter may use a developer's GPL `libx264` build from `PATH`; it is flagged `lgpl_safe: false` and must not ship.
- Every user-facing action needs an MCP tool and CLI command with identical behavior (including undo and confirmations).
- Errors use the shared codes in `specs/README.md` (`invalid_input`, `permission_missing`, `job_failed`, etc.), which map to CLI exit codes.
- Definition of Done includes `cargo clippy -D warnings`, `cargo fmt`, tests, and manual scripts at `tests/manual/<ID>.md` where automation is impossible.
- No telemetry and no network traffic when destinations and AI keys are off.
- UI text is translatable: wrap it with `cm_i18n` (see Current state); brand marks use the theme's text colour, never a service's own colour (OD-21).
