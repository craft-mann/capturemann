# Implementation plan

Source of truth for scope is `specs/` (see `specs/README.md` for conventions and Definition of Done). This file orders the work. Milestones and gates follow `specs/04-delivery-plan.md`.

## Working rules

- One crate or feature per commit; tests cite acceptance criteria as `AREA-n.ACm`.
- Every user-facing action ships with its MCP tool and CLI command in the same change.
- Errors use the shared codes in `specs/README.md`; no panics in UI callbacks.
- Windows cannot be verified locally yet: it is covered by `tests/manual/<ID>.md` (CI runs on macOS only until the Windows milestone), and noted as such.
- Spike code (`spikes/`) is reference only; product code is designed per `specs/01-technical-design.md` (for example, no raw-frame pipe to FFmpeg for recording).
- Read the relevant `specs/features/*.md` before starting each feature.

## Step 0: Housekeeping (done)

Stray files removed, spikes moved to `spikes/`, `specs/` un-ignored, `confirmation_timeout` fixed, S1–S3 marked Go on macOS, workspace skeleton, CI (fmt, clippy `-D warnings`, tests on macOS and Windows, cargo-deny) and `deny.toml`.

## M0: Foundations and spikes (weeks 1–3)

1. `cm-core`: `MediaTime`, geometry, actions and commands, undo stack, revisions (`user` / `agent:<name>`), shared error codes and CLI exit codes.
2. Spike S4 cursor telemetry (`spikes/spike-cursor`).
3. Spike S5 UI framework, GPUI vs iced (`spikes/spike-ui-*`), recommendation into `docs/project/spikes.md`.
4. Spike S6 4K60 hardware encode + 1080p camera + bubble window exclusion. Gate: ≤ 1% late frames.

## M1: Screenshot and annotation (weeks 4–7)

Features CAP-1…5, ANN-1…3, LIB-1/2 (read `features/01`, `02`, `09`).

1. `cm-library`: `.cmshot` bundle, manifest, SQLite index.
2. `cm-capture`: display, window and region capture, scale handling.
3. `cm-render`: annotation ops via `tiny-skia` (non-destructive, stored in the manifest).
4. `apps/overlay`: region picker, hotkeys, tray (per S2 findings).
5. `apps/desktop`: editor canvas and library, following `docs/development/design-surfaces.md` (surfaces mapped to the design kit in `design/`). Framework per S5.
6. Clipboard and save to destination (CAP-4).

## M2: Agent layer and jobs (weeks 8–9)

Features AGT-1…3 (read `features/12`, `specs/02-agent-interface.md`).

1. `cm-daemon`: action bus, sessions, event stream, JSON-RPC over local IPC.
2. Confirmation gate (5 min, one dialog at a time).
3. `cm-jobs`: persistent queue, retries, progress events.
4. `cm-cli` and `cm-mcp`: screenshot and annotate tools first, `request_id` idempotency.
5. Gate: an MCP client captures, annotates and exports end to end.

## Interim exporter (decided and built Oct 21, 2026, ahead of M4)

`cm-media` renders one combined MP4 per recording (screen + round camera bubble + mic/system audio) with the FFmpeg sidecar into `exports/`. Job type `export`, action `export_video` (preset `quick` by default), `capturemann export`, setting `export.auto_on_stop` (skipped with an `export.skipped` hint when no FFmpeg is found). Encoder order: VideoToolbox, `h264_mf`, nvenc, qsv, amf, `libopenh264` and `libx264` last; the last two are used only when the FFmpeg on hand has them (a developer's FFmpeg: the shipped LGPL FFmpeg has neither, and the app has no OpenH264 of its own); `libx264` is GPL and flagged not LGPL-safe; capped at 4096 per side; retry only on encoder-init failure. M4 keeps this interface. **Edited export (built Oct 22, 2026):** when `manifest.edits[0]` changes the picture (a cut, a speed span, a trim, a background; a list without `version` is the recorder's untouched entry), `export_quick` renders through `cm_render::Compositor` instead of the FFmpeg graph: one FFmpeg decoder per kept piece (seek, `setpts`, `fps`, NV12), a compositor frame per output frame, RGBA over a pipe to one FFmpeg that encodes (hardware first, same fallback rules) and muxes the audio: each source is decoded to f32, mixed by `cm_audio::mix` through the `AudioProcessor::mix` hook (gains and mutes of `set_audio_mix`, cuts, pitch-preserving speed changes, optional `loudness_lufs` with the -1 dBTP limiter) and passed as one raw PCM input (the FFmpeg `atempo` graph stays as the fallback for a processor without `mix`). Pause gaps are skipped like cuts, in the export and in the duration the daemon reports (`EditList::without_pauses`). A compositor failure (no GPU adapter) fails the export; it does not fall back to ignoring the edits. Measured on an Apple M4 Pro: a 30 s 1080p fixture with a frame, a bubble and a cut exports at 6.5x real time (VideoToolbox), the plain FFmpeg graph at 7.3x. **Presets and GIF/WebM (built Oct 22, 2026):** `export_video { preset | format, width, fps, max_mb }` (table `crates/cm-media/data/presets.toml`, replaceable at run time through `CAPTUREMANN_PLATFORM_RULES`; `cm_media::preset` resolves a preset for a recording and refuses an enlargement where the preset forbids it; `cm_media::check_request` is the check `export_video` runs before queuing); the compositor path draws every preset frame, GIF is the compositor + a lossless FFV1 step + palette steps, WebM is VP9 + Opus; measured on an Apple M4 Pro for a 30 s 1080p fixture with a bubble and audio: `youtube-1080p` 6.8x, `vertical-1080` 6.8x, `square-1080` 9.0x, `source` 7.0x, `gif` (fit under 10 MB) 16.5x, `webm` 7.0x real time (timing probe `timing_presets_30_s_1080p_fixture`, not a stored report). **Open:** the bundled FFmpeg has the WebM encoders (libvpx VP9 and libopus, built in, Oct 22, 2026); the EDT-5 reframe; the Source stream-copy fast path (`source` re-encodes today); a browser playback check of the WebM; long clips; Windows. Still open: annotations and cursor in video, per-segment layouts, a stored report of a long export. Known gaps: no loudness normalization, bubble layout at stop only, FFmpeg found on `PATH` until the LGPL bundle exists (`CM_FFMPEG_BUNDLE` can bundle one).

Decided or recorded Oct 21, 2026 (review and fix wave):

- **Launch at login is default off** (explicit opt-in), a LaunchAgent for installed bundles only, kept as a preference file and not as a setting an agent can change. This deviates from CAP-2.AC5's original "default on"; the maintainer decided on Oct 21, 2026 that it ships default off and stays off (OD-13), to be revisited with an installer.
- **Studio and the permissions screen are not hardened** with `sharingType = none` (a user may want an OS screenshot of the app); the HUD, bubble, countdown, toasts, start sheet, confirmation dialog and launcher are, and the engine excludes the whole process by pid in recordings. Screenshots exclude own windows through ScreenCaptureKit on macOS 14+.
- **Amended Oct 21, 2026 (maintainer's decision after a real run):** excluding the whole process also hid the library/Studio window, so a display recording showed only the desktop layer behind it. Recordings and screenshots now capture everything on screen except the recorder UI: the process stays excluded by pid, with the Studio window (editor and setup screens included) kept through `exceptingWindows`. The app publishes the Studio window id from the main thread, and the capture filter re-reads it every second, so a Studio window opened or closed mid-recording lags by up to about 1.5 s. An id not yet listed stays excluded (fail-safe). Spec: REC-6.AC8.
- **Per-client policies are not a security boundary.** They are keyed by a self-declared name; the confirmation gate, the app-only settings list and the resource limits are what hold against a hostile local process.
- **Auto-export is skipped without FFmpeg** (`export.skipped`), instead of queuing a job that is sure to fail.
- **Windows is compile-only** until the Windows milestone; no status may imply it runs.
- **OpenH264 is removed (maintainer chose option (c), Oct 24, 2026; it had chosen (a) on Oct 22).** Cisco's patent coverage applies only to its own prebuilt binaries, not to a source build, so shipping the `openh264` crate would have made the project carry H.264 patent exposure for a fallback that should almost never run. Every supported Mac (macOS 13 and later; Apple silicon, or Intel from about 2016) has a hardware H.264 encoder through VideoToolbox, Windows has the licensed Media Foundation software encoder, and the bundled LGPL FFmpeg has no software H.264 encoder either. The fallback code, the dependency and its tests are deleted; Macs without a hardware encoder fail the start with a clear message. Revisit only if real users hit it: the option then is Cisco's binary downloaded once after consent.
- **whisper.cpp comes through `whisper-rs`, whose licence is the Unlicense (Oct 22, 2026).** The binding crates (`whisper-rs`, `whisper-rs-sys`) declare the Unlicense, a public domain dedication, which is not on the `deny.toml` allow list; they are allowed by name (`exceptions`), so any other Unlicense dependency still fails the check. The code they compile (whisper.cpp, ggml) is MIT, and `gen-third-party.sh` now picks up the MIT notice that `whisper-rs-sys` keeps one folder down. Model downloads use `ureq` with the system TLS stack (`native-tls`), which avoids bundling `ring` and a root certificate list. Whisper model files are not part of the app: the user downloads or imports them (see M5 in the plan).
- **The MCP server is the `cm-mcp` binary**; `capturemann mcp` launches it.
- **Decided by the maintainer (Oct 21, 2026):** OD-12 (destructive confirmations use the normal primary button as DESIGN says; no amber fill; `ButtonKind::Danger` now renders as Primary: done) and OD-13 (launch at login stays default off).
- **M4 gate test and manual kit (Oct 22, 2026).** `cargo test -p cm-desktop --test parity` renders sampled frames of six edit lists through the editor's preview and through the export and compares them (mean error, PSNR, bad-pixel share, frame shift of at most one; control case measured at about 0.6 of 255 and 36 dB; needs FFmpeg and a GPU, else SKIPPED; tested on this Mac, no stored report). It found two things: the compositor export wrote untagged video converted with FFmpeg's BT.601 default, so players would shift every colour (fixed: BT.709 matrix, limited range and stream tags in `edited.rs`), and the preview draws a fixed bottom-left bubble while the export draws the stored layout (the ignored test `m4_gate_bubble_layout_matches` fails with mean error about 10 until CAM-3 reads the stored layout in the preview; remove its `#[ignore]` then). Open from the same work: the default in-point differs (untouched `quick` export 12.0 s from the screen's first frame, any stored edit uses `live_at` and gives 11.81 s on the fixture); check that real masters are tagged BT.709 (`tests/manual/M4-GATE.md`). The synthetic recording is `cargo run -p cm-daemon --example make_fixture`; the scripts are `tests/manual/M4-GATE.md` and the files it lists; reports go in `verification/`.
