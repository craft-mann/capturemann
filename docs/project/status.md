# Project status

A dated log of what is built and how it was checked, kept out of `CLAUDE.md` so that file stays a short guide. The delivery plan is [`plan.md`](plan.md); the open verification work is in `specs/04-delivery-plan.md` (**Verification debt**).

CaptureMann v0.1 is a free, Apache-2.0, pure-Rust desktop app (v0.1 is macOS 13+ on Apple Silicon only; Intel Macs, then Windows 10 22H2+, then Linux follow, maintainer decision Oct 24, 2026) for screenshots and screen recording (up to native 4K/5K, webcam bubble), with local folders and Google Drive for storage and YouTube for publishing (scope decision Oct 23, 2026: OneDrive and Dropbox are built but "Coming soon"; TikTok and Facebook Pages are deferred; both are open for community contributions, see CONTRIBUTING.md). Every feature is also exposed to AI agents via MCP and a CLI.

The repo is a Cargo workspace (`Cargo.toml`, `crates/*`, `apps/*`; `spikes/` is a separate workspace; `rust-version = "1.95"`). Status as of Oct 21, 2026 (details in `docs/project/plan.md`, `specs/04-delivery-plan.md` including its **Verification debt** section, and each feature file's Status):

- **Built (macOS):** `cm-core` (with the edit list and timeline math of EDT-1 to EDT-5), `cm-capture` (screenshots, the screen recording track, disk guard), `cm-camera`, `cm-audio` (capture, plus `mix`: gains, R128 loudness, limiter, pitch-preserving stretch), `cm-cursor` (telemetry capture, plus `view`: the cursor path, smoothing, click effects and the zoom and reframe camera), `cm-encode` (hardware fMP4 writer: VideoToolbox on macOS; no software H.264 fallback, a rejected hardware encoder fails the start with `platform_rejected` / `hardware_encoder_unavailable`), `cm-render` (annotations; Auto-redact's `ocr` module (ANN-2.AC4: the `TextRecognizer` trait, Apple Vision on macOS through `objc2` messages, an unavailable stub on Windows, a scripted fake, and the pure detector for emails, keys and tokens, phone numbers and IPv4 addresses; tested with fakes, and the Vision path ran once on a synthetic PNG in an ignored test); and the headless `wgpu` frame compositor `compose::Compositor` (with the burned-in caption layer), tested with goldens on an Apple M4 Pro, the edit-list export path in `cm-media` feeds it: tested with FFmpeg and a GPU on this Mac, not on CI), `cm-jobs`, `cm-library` (`.cmshot` and `.cmrec` bundles, SQLite index, crash recovery), `cm-daemon` (action bus, JSON-RPC, confirmation gate, per-client policy, settings store, recording engine and self-test, export hook, the library watcher: a 2 s polling scan that indexes bundles added, removed, renamed or edited outside the app and publishes `capture.*` events; tested with fakes, not seen by eye), `cm-ipc` (client side of the daemon IPC), `cm-ai` (AI-1 engine, AI-3 and AI-4: the Whisper model store with user-started resumable downloads, the whisper.cpp transcriber, captions with SRT, VTT and TXT, burned-in captions (compositor layer, show and burn-in switches), auto-zoom and silence and filler cut suggestions; tested with fakes and synthetic inputs, plus an ignored real-model test (`small` on this Mac: a 5 s speech clip at about 15x real time); the maintainer also ran `small` and `medium` by hand on real recordings (as reported, not stored); the daemon, MCP and CLI surface for the AI actions is built and wired to the real engine (`cm_daemon::ai_engine`, in the app and the headless daemon)), `cm-media` (FFmpeg-sidecar exporter: the interim `quick` preset, the edit-list export through the compositor, the EXP-2 platform presets and EXP-3 GIF/WebM; and `decode`: the continuous preview decoder, one FFmpeg process per track with a frame cache, measured at 500 to 1900 fps for 1080p and 4K sources on an Apple M4 Pro), `cm-mcp` (MCP server binary, 55 tools, plus resources (library, jobs, capture, transcript, YouTube rules; 1 MB bound) and six prompts, built Oct 24, 2026 and tested with fakes only, including `list_publish_accounts` and `publish_video`) and `cm-cli` (the `capturemann` binary), plus the M6 start (Oct 23, 2026, tested with fakes): `cm-publish` (the `PublishProvider` trait, platform rules and validation, the YouTube provider with a fake server, the accounts file and the Pacific-day upload counter; in `cm-daemon` the `publish_video` engine (Confirm dialog built from the validated plan, never public by default, `export_path` or `export_preset`) and the resumable `publish` job (held while recording, retried, `auth_expired` pauses it, `publishes[]` record in the manifest, events `publish.queued` and `publish.done`), with `capturemann publish` and `publish accounts`; never run against a real YouTube account); `cm-auth` (PKCE loopback OAuth, keychain secrets, token refresh; never run against a real provider) and `cm-storage` (the `StorageProvider` trait, the local folder, drive and NAS provider, the destinations file; the `upload` job and the `list_destinations` and `upload` actions are in `cm-daemon`, and Settings → Destinations manages local folders and connects Google Drive: guided BYO setup, browser sign-in, Test connection, Reconnect, Disconnect; the daemon's `KeychainTokens` is the keychain token source; `retry_job` re-queues failed, cancelled or `auth_expired` jobs; none of it run against a real Google account or seen by eye). Apps: `apps/overlay` (region picker) and `apps/desktop` (GPUI shell, library, tray, hotkeys, annotation editor, launcher, permissions screen, start sheet, recording HUD, countdown, bubble, and the recording editor view for EDT-1 to EDT-5, and the AI page with the model manager, caption editor and suggestion lists, untested by eye).

- **UI languages (Oct 24, 2026):** English is the default and the app switches language only when the user picks one (Settings → General → Language: English, Tiếng Việt; `appearance.language`, app-only). The `cm-i18n` crate holds the `.po` loader, the macros and the locale-aware formatting; catalogues are `locales/*.po` with English as the msgid. **Every user-visible string goes through `tr!`, `tr_ctx!` or `trn!` (a ratchet test keeps the unwrapped count at 0), with whole sentences and named placeholders, never concatenated; display text is rendered at paint or rebuilt on a language switch, not cached in a `String`.** The daemon's confirmation texts and errors are translated in the app from `kind` and `params` (`apps/desktop/src/daemon_text.rs`, `cm_core::message`); CLI, MCP, JSON-RPC, logs and the macOS permission prompts stay English. `locales/vi.po` is a complete draft awaiting the maintainer's review (`locales/vi-review.md`). Layout guards: `apps/desktop/tests/layout_guard.rs` and the font-metric width tests (`design/i18n-STATUS-overflow.md`): a text child in a flex row needs `min_w(0)` or the helpers in `ui/components.rs`. Plan and reports: `specs/plans/i18n-plan.md`, `design/i18n-STATUS.md`. Text fields support input-method composition (Telex, VNI) and grapheme-aware editing; the bundled Geist 1.8.2 covers Vietnamese. Tested with fakes; the maintainer has used the Vietnamese UI and the fixes it led to are in.

## Release 0.1.0 (Oct 26, 2026)

Released: signed (Developer ID), hardened, notarized (submission `70a3df49-d81f-4ba2-8458-530c63871ca3`, Accepted) and stapled DMG `CaptureMann-v0.1.0-macos-arm64.dmg` (sha256 `3d9822246dea1acc414fb30e58ef419bb6e56676154c518295a16aa74b0e2e05`) at <https://github.com/craft-mann/capturemann/releases/tag/v0.1.0> (tag `7fe4c97`). `make verify-release` passed with no warnings. The maintainer installed it on the build Mac (normal download dialog, permissions, short recording, YouTube publish; as reported). Report: `verification/RELEASE-0.1.0-2026-10-26-maintainer.md`.

- **Install paths:** DMG, or `brew install --cask craft-mann/tap/capturemann` (tap `craft-mann/homebrew-tap`; update it after each release with `scripts/update-homebrew-cask.sh`). The official `homebrew/cask` needs notability (about 75 stars) and is skipped for now. The CLI is inside the app; Homebrew links it, a DMG user links it by hand (README, user guide).
- **Not done:** the `Release` workflow has never run on GitHub (needs five secrets; test on a fork first); a first-install check on a second Mac or user account; the website download link. Mac App Store is not feasible as-is (App Sandbox conflicts with the CLI/MCP socket, the input-monitoring cursor telemetry, free library paths, the login item and the FFmpeg and `afplay` child processes).
- **Repo hygiene:** rulesets "Protect main" (no deletion, no force-push) and "Protect release tags"; PR and required-check rules deferred until there are contributors; Dependabot monthly and grouped, no major bumps for the GPUI-pinned crates.
- **Reports:** `make report` writes `reports/` (tests, Trivy, cargo deny, SBOM); the latest snapshot is 3234 passed, 0 failed, 41 ignored.
- **Next:** Intel Macs (universal build), then Windows, then Linux (`plan.md`).
