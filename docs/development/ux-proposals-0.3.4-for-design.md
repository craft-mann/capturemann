## 1. Introduction and how to read this file

### What CaptureMann 0.3.4 is

CaptureMann is a free desktop app (macOS, Windows, Linux) for screenshots and screen recording, with a library, an editor, local folders / Google Drive for storage and YouTube for publishing. Every feature is also exposed to AI agents (MCP) and a command line (CLI), so some flows start without a person at the screen. The UI is dark first (light theme exists), Geist type, 40 px controls, 44 px HUD targets, red "rec" colour. The design pack for this release is `specs/capturemann-0.3.4-design/` (boards S0 to S23).

0.3.4 adds: **Long Shot** (scrolling capture, Auto or Hand scroll), **Click Guide** (a step-by-step how-to built from your clicks, exported as Markdown / HTML / PDF / rich text), **Boards** (several screenshots on one canvas: Pair / Grid / Strip / Free), **Bulk export** (many screenshots at once with size, format, watermark), the editor tools **Retype**, **Move area**, **Blueprint**, **Zoom Lens**, canvas text selection, library hover-selection, sidebar tiles, and an Agents & CLI status icon.

### Important limit of the evidence

Almost every floating window (Long Shot bar, HUD, side preview, Click Guide bar, countdown, window picker, toasts, confirm dialogs, launcher) is excluded from screen capture, so the QA agents on macOS and Windows could measure and read them through the accessibility tree but **could not look at them**. Findings about those surfaces are about sizes, text and behaviour, not about how they look. A human look at those surfaces against the boards (S2, S2b, S3, S16 to S18, S20) is itself a request (items LS-18 and CG-18).

### How each item is written

Each row has: **ID** (stable prefix per surface), **Today** (what a user sees), **Problem** (as an end user feels it), **Evidence** (screenshot name in `verification/QA-0.3.4-shots/` and/or report), **Direction** (suggested, not decided), **Needs** (Design = a drawing or a design decision is needed; Copy = wording only; Behaviour = a rule/engineering change a designer should know about; Review = look at it on a real screen), **Pri** (P1/P2/P3), **Eff** (engineering effort S under a day, M 1 to 3 days, L more).

Status marks added in this update: **Fixed in code (commit); design review of the state still open** = the behaviour was changed on `main` but the designed state (toast, bar, HUD text) has not been seen on a screen or drawn; **Retired** items (fully fixed, nothing to design) are removed from the tables and listed in section 4, their IDs are not reused. Priority: where an audit rated the item (P1/P2/P3 in the two UX audits) that rating is kept. QA-only items carry a **mapped** rating (marked with `*`): QA severity high/medium = P1, low-medium = P2, low = P3. Effort without an audit estimate is mine (marked `~`). Status notes ("seen fixed", "unconfirmed") come from the later QA passes; an item can already be fixed in code, check the source before spending design time.
