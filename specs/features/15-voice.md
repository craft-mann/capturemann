# Voice and meetings (VOC)

Audio-only recording for meetings (online and in the room), interviews, one-on-ones, lectures, product introductions and voice notes. It reuses the recording engine (one session clock, one track per source, crash-safe WAV masters from AUD-1 and AUD-2), the `.cmrec` bundle and the library; the transcript, translation, speaker labels and reports come from AI-1, AI-5, AI-8 and AI-9. Plan, model choices and spikes: `../plans/voice-and-meetings-plan.md`.

VOC-1 and VOC-2 ship in release 0.2.0 (Oct 27, 2026: built and tested with fakes; the maintainer's own use of the latest dev bundle on one Mac, as reported, with no stored report; the hardware checks below are pending). VOC-3 is deferred to a later 0.2.x. There is no release date; the maintainer cuts it. "P1" means in 0.2.0.

### VOC-1 Audio-only recording
**Priority** P1 · **Status** In progress (built in 0.2.0: the daemon side, the Record sheet's Audio mode, the compact HUD, markers, the consent line, the shortcuts, tray and launcher entries, the sidebar mic button and the Audio library view; tested with fakes; recording audio worked on hardware as reported by the maintainer on Oct 27, 2026, a manual use with no stored report; pending, owner the maintainer: the hardware checks of `tests/manual/VOC-1.md` with a `verification/` report, namely AC2 (10-minute call, 50 ms), AC5 (kill -9, 299 s kept), AC6 (3-hour soak, under 200 MB), lid and sleep, and the consent and marker steps) · **Crates** cm-audio, cm-daemon, cm-library, apps/overlay, apps/desktop · **Depends on** AUD-1, AUD-2, AUD-3, AUD-6, REC-4, REC-5, REC-8, AGT-2, DESIGN §5.2, §5.7

**As built (Stage 0, Oct 26, 2026; tested with fakes; the recording itself has since worked on the maintainer's Mac, as reported, Oct 27, 2026).** `cm-library` has `CaptureKind::Audio`: an audio recording is a `.cmrec` whose manifest says `"kind": "audio"` (the index kind comes from the manifest, the folder extension stays `cmrec`; the index schema moved to version 3 and migrates in place, so transcript search rows survive). `manifest.markers` holds `{ at (ticks of recorded time, pauses removed), label?, by? }`. `start_recording { mode: "audio", mic?, system_audio?, preset?, title?, max_duration_s?, countdown_s? }` runs through the action bus: `RecordingSession` takes only mic and system tracks (no screen, camera or cursor), `invalid_input` names the screen-only field (AC9), the Confirm dialog says "Record audio" with the microphone name and no screen target and always carries the consent line (AC7, AC8), a microphone-only plan never asks for Screen Recording and system audio without it is `permission_missing` `screen`, the OS idle-sleep assertion sits behind `IdleSleepInhibitor` (real adapter wired only in `DaemonBuilder::recording_system`, untested), a wall-clock jump stops the recording with `reason: "system_sleep"`, and `max_duration_s` defaults to `recording.audio_max_duration_s` (4 h, at most 12 h). `add_marker` (MCP tool, `capturemann record marker`) marks the running recording at the HUD timer or a finished one at `at` (one revision and undo step), and `list_library { kind: "audio" }` filters. A crashed audio recording is recovered from its WAV files with its kind and markers (library test; the `record_e2e` example still records a screen and has no audio-only mode, so the `kill -9` check on real hardware is a manual step, still pending). `make_fixture --audio-only` writes a synthetic audio bundle. Settings: `recording.consent_notice` (default on, app-only) and `recording.audio_max_duration_s` are read by the daemon; the ⌥⇧V and ⌥⇧M shortcut entries live in the desktop shortcut table (built in Stage 1, below).

**As built (Stage 1 UI, Oct 26, 2026; tested with fakes, not checked by eye).** *Sheet* (`recording::audio_sheet`, drawn by `ui/recording/sheet/audio.rs`): the header has a Screen / Audio switch (⌥⇧R / ⌥⇧V) and the sheet grows to 760 px in Audio mode; five preset cards (In the room, Online meeting, Lecture or talk, Product demo, Voice note) set the sources and the suggested report; Microphone has a device picker and a live 40-segment meter (`cm_audio::MicMonitor`, a level only, opened only when the microphone is on and macOS already allowed it, closed before the recording starts and when the sheet closes); System audio has its switch and the Screen Recording note (a microphone-only start never mentions it); "How many people?" (Not sure, 2, 3, 4, 5+; hidden for a voice note) is sent as `people` (AC11, "As built, How many people?" below); the "After you stop" chips follow `ai.auto_transcribe`, the installed model and `ai.auto_speakers`; the consent line shows while `recording.consent_notice` is on (every time for presets with other people, once for a voice note) and "Don't show again" writes the setting; the footer line shows disk per hour with the free space (about 0.7 GB for the microphone, doubled by the denoised copy, 1.4 GB for system audio), "Keep the lid open" for In the room, and the length limit. Start sends `start_recording { mode: "audio", preset, mic, system_audio }` through the daemon and remembers the preset and sources (`recording.audio_preset`, `recording.audio_mic`, `recording.audio_system_audio`, `recording.audio_seen`; agent-writable like the rest of `recording.*`). A microphone macOS never asked about is asked on Start (the user's own press), then Start is pressed again.

*HUD*: the audio bar is Stop, the timer, a 14-bar mic meter, Pause or Resume, Mute mic, Marker (with the M hint), Discard, then the "Started by" chip; no brackets, camera, Draw or Restart, and no area indicator window. A marker made by the user (button, M while the bar has the focus, ⌥⇧M) shows "Marker at 12:48" with an optional label field in the strip above the bar for 8 s; Enter names it, Esc or the timeout leaves it unlabelled. **Daemon change for this:** `add_marker { at, label }` without `capture_id` gives the marker already set at that recorded time its label (`relabel_marker`; the running form had no way to name a marker after setting it); tested in `voice_audio.rs`. *Entry points*: ⌥⇧V (starts with the last preset and sources and shows the consent line as a toast while it is on; stops an audio recording; says "A recording is already running" over a screen one), ⌥⇧M (marks the running recording, or says there is none), the tray's "Record audio" (opens the sheet in Audio mode) and the launcher's "Record audio" command. Settings → Shortcuts has both rows in the Recording group, with conflict checks and Reset. Manual script: `tests/manual/VOC-1.md`. The HUD's label field is the only toast-like surface (no separate marker toast window).

**As built (Stage 1, P1.3 and P1.4 UI, Oct 26, 2026; tested with fakes, not checked by eye).** The sidebar has an **Audio** item (icon `audio-lines`, route `Route::Audio`, `Filter::Audio`, `list_library { kind: "audio" }`) between Recordings and Screenshots, with the real count (the unfiltered load counts `kind: "audio"`); All captures shows audio too and its count includes it. The dock has a 42 px rec-tinted mic button "Record audio" next to Record… and the rail has the same button under Region; both carry the chord hint and call `ui::sidebar::open_record_audio`, which opens the Record sheet in Audio mode. The Audio page has the header count, search ("Search titles and what was said", the LIB-1 search over titles and transcripts) and a Record audio button; an empty library shows a "No audio recordings yet" state. Cards draw the waveform on the board's dark tile, the preset chip (read from the manifest key `preset`, else a generic "Audio" chip; Stage 0 does not store the preset yet), the duration, and badges for transcript (`transcript.json`), speakers (manifest `speakers`) and report (`reports/` or manifest `reports`), with "N speakers" in the meta line. Waveform peaks: `cm_library::audio` streams the mic and system WAV tracks into 96 bars (loudest wins, square-root curve, floor 6 of 255) and caches them in `peaks.json` in the bundle, keyed by the source file names and sizes; the desktop reads them off the UI thread (`ui/audio_cache.rs`). Unit tests cover the peaks (synthetic WAVs, 16-bit and float, stereo), the cache and its refresh, the card facts, bar pooling, the nav model and the Audio parse. Opening an audio card opens the audio editor (VOC-2); an audio recording has no details page (the editor has Reveal in Finder). No screenshot comparison with board V3 is stored.

**User story** — As someone running an interview, a meeting or a one-on-one (online or with my laptop on the table), I want to record just the audio, so that I get a full recording, a transcript and an AI report afterwards without recording my screen.

**Description**
- **A third capture mode.** "Record audio" sits next to the screenshot and screen-recording entries: tray menu, launcher (LNC-1), the start sheet's mode switch (Screen / Audio), and a new default shortcut **⌥⇧V** (Windows Ctrl+Alt+Shift+V), configurable with the others (CAP-2). An agent uses `start_recording { mode: "audio" }`.
- **Sources.** Microphone (AUD-1 device picker and level meter, noise suppression per AUD-3), system audio (AUD-2), or both. Default: microphone only. Each source is its own track, exactly as in a screen recording (`mic.wav` / `mic.denoised.wav`, `system.wav`). No screen, camera or cursor track is opened, and **Screen Recording permission is not requested for microphone-only recordings** (macOS needs it only when system audio is on, because system audio comes from ScreenCaptureKit; the sheet says so next to the switch).
- **Use-case presets in the sheet** (they only set defaults and the AI-9 template suggested after stop; the user can change every source):

| Preset | Sources | Report suggested after stop |
| --- | --- | --- |
| In the room (interview, 1:1, meeting around a laptop) | Mic | Meeting minutes, or Interview notes when chosen |
| Online meeting (Zoom, Meet, Teams, a browser call) | Mic + system audio | Meeting minutes |
| Lecture or talk | Mic | Lecture notes |
| Product introduction / demo call | Mic + system audio | Product presentation recap |
| Voice note | Mic | Summary |

- **Bundle.** A `.cmrec` with `kind: "audio"` in the manifest and no `screen.mp4`; the library index stores `kind = audio`. Everything that works on a recording's audio (transcribe, captions, AI-4 suggestions, trim and cut, upload to a destination) works unchanged.
- **HUD (DESIGN §5.2, compact variant).** Timer, mic level meter, Pause/Resume (REC-4), Mute mic (AUD-6), **Marker**, Stop, Discard. No area brackets (there is no area). The tray shows the recording state as for screen recordings (REC-5); an agent-started recording shows the same agent notice.
- **Markers.** The Marker button or **M** while the HUD is focused, the global shortcut ⌥⇧M (Ctrl+Alt+Shift+M), or `add_marker` adds `{ at, label? }` to `manifest.markers` (session time, so pauses don't shift them). Markers show on the editor's waveform and in AI-9 reports ("Marked moments").
- **Consent notice.** Recording other people without telling them is illegal in many places. The first audio recording, and every recording whose preset involves other people, shows a one-line notice in the start sheet: "Let everyone know they're being recorded." with "Don't show again" (setting `recording.consent_notice`, default on). The agent confirmation dialog always carries the same line. CaptureMann gives no legal advice beyond this line.
- **Long sessions.** Supported up to `max_duration_s` (default 4 h for audio, configurable to 12 h). While recording, the app holds an OS "prevent idle sleep" assertion (macOS `IOPMAssertion`); closing a laptop lid without an external display still sleeps the Mac, so the sheet's In-the-room preset shows "Keep the lid open". Disk use is shown before start: mic about 0.7 GB per hour (48 kHz 32-bit float mono master plus the denoised copy is about 1.4 GB), system audio about 1.4 GB per hour; the disk floor (NFR-7) applies.
- **After stop.** The bundle opens in the audio editor (VOC-2). When `ai.auto_transcribe` is on and a model is installed, transcription starts as for screen recordings (AI-1), followed by speaker labels (AI-8) when the setting `ai.auto_speakers` is on (**default on** since the maintainer decision of Oct 27, 2026; the daemon runs it after any transcript, with the count from the recording's `people` answer or the preset, and does nothing when the speaker models are missing or the recording is a voice note).

**Acceptance criteria**
- **AC1** Given Audio mode with the microphone only, when the user records 60 s, then the bundle has `kind: "audio"`, a 60 s ± 20 ms mic track, no screen, camera or cursor files, and no Screen Recording permission prompt appeared.
- **AC2** Given mic and system audio, when a call plays through the speakers for 10 minutes, then both tracks exist and their start and end stay within 50 ms of each other on the session clock (NFR-3).
- **AC3** Given ⌥⇧V, then an audio recording starts with the last-used sources and the compact HUD shows timer, level meter, pause, mute, marker and stop.
- **AC4** Given the user presses Marker at 02:00, then `manifest.markers` holds an entry at 120 s ± 50 ms, and after a 30 s pause at 01:00 the marker is still at 120 s of recorded time (pauses removed).
- **AC5** Given the process is killed (`kill -9`) 5 minutes in, when the app starts again, then the recording is recovered with at least 299 s of audio (REC-8, AUD-1 header repair).
- **AC6** Given a 3-hour mic + system recording, then memory stays under 200 MB and the drift between the two tracks stays under 50 ms at the end.
- **AC7** Given the consent notice is on, then the start sheet shows it before Record, and an agent's `start_recording { mode: "audio" }` dialog contains the same sentence.
- **AC8** Given an agent calls `start_recording { mode: "audio", mic: true }`, then the Confirm dialog says "Record audio" with the microphone name and no screen target, and on approval a `kind: "audio"` recording starts.
- **AC9** Given `mode: "audio"` together with `target`, `camera`, `fps`, `size`, `codec`, `quality` or `cursor`, then the call fails with `invalid_input` naming the field and nothing starts.
- **AC10** Given the library, then audio recordings appear under a new **Audio** sidebar item (with count) and in All, each with a waveform thumbnail, title, date and duration; transcript search (LIB-1) finds them.
- **AC11** Given `start_recording { mode: "audio", people: 4 }` (or `record start --audio --people 4`, or "4" under "How many people?" in the Record sheet), then `manifest.settings.people` is 4 and the automatic speaker step (AI-8) asks for exactly four speakers; `people` outside 1 to 8, not a whole number, or without `mode: "audio"` fails with `invalid_input` naming `people` and nothing starts; without it the preset decides (room 2, voice note 1 = no speaker step, otherwise 3), and the Speakers tab's "How many people?" starts on the stored value.

**Edge cases and errors**
- Microphone permission missing → `permission_missing` (`microphone`) before the dialog, as REC-1.
- System audio requested without Screen Recording permission → `permission_missing` (`screen`) with "System audio needs Screen Recording permission on macOS"; the sheet offers microphone only.
- Mic disconnected mid-recording → AUD-1 behaviour (`audio_device_*` warning, silence, switch to default if chosen).
- Mac goes to sleep (lid closed) → recording stops with `reason: "system_sleep"` and keeps what was captured.
- A screen recording is running → `busy`, as REC-1.AC6.

**Agent interface** — `start_recording { mode: "audio", mic?, system_audio?, preset?: "room"|"online"|"lecture"|"product"|"note", people?: 1..8, title?, max_duration_s?, countdown_s? }` (**Confirm**, OD-24 policy applies) → the same result object as REC-1 with `tracks` listing only audio tracks. `add_marker { recording_id?, label? }` → `{ marker }` (Free; also allowed after stop with `capture_id` and `at`). Pause, resume, stop, status and events as REC-1/REC-4. CLI `capturemann record start --audio [--mic <id>] [--system-audio] [--preset room] [--people 3]`, `capturemann record marker [--label ...]`. `list_library { kind: "audio" }`.

**As built (Oct 27, 2026, "How many people?" per recording; tested with fakes, the app not launched)** — `start_recording` takes `people` (1 to 8, audio mode only); it is saved in `manifest.settings` beside `preset` (the manifest `settings` object is free-form, so no schema version or index migration is needed; older recordings simply have none). The Record sheet sends its answer (2, 3, 4, and 5 for "5+"; "Not sure" and a voice note send nothing), and the shortcut and launcher start without one. The Speakers tab's "How many people?" starts on the stored value (5 to 8 show as 5+), then on the preset's guess, until the user picks. The Record sheet's "After you stop" row shows the speaker step as part of the default plan.

**Out of scope** — Capturing one app's audio only (P2, ScreenCaptureKit per-app filter), phone or Bluetooth hands-free call capture, meeting bots that join calls, calendar integration and automatic meeting detection (P2), compact masters (FLAC/AAC) instead of WAV (decided Oct 26, 2026: masters stay WAV; compacting is P2).

**Test notes** — Integration tests with scripted audio devices (no screen track, manifest kind, markers through pauses); kill -9 recovery test; 3-hour soak on hardware (`verification/` report); manual script `tests/manual/VOC-1.md` (permissions, consent notice, HUD, lid-open hint).

### VOC-2 Audio editor view and audio export
**Priority** P1 · **Status** In progress (built in 0.2.0: the audio export and the editor view with markers, the Transcript, Speakers and Report tabs and the Export audio sheet; tested with fakes and, where FFmpeg is installed, with golden tests; the maintainer's use of the app on Oct 27, 2026, as reported, covered recording and the editor in general, not the export checks; pending, owner the maintainer: `tests/manual/VOC-2.md` with a `verification/` report for the WAV and M4A exports and the loudness, and AC5 (60 minutes in 60 s) is not measured) · **Crates** apps/desktop, cm-media, cm-daemon · **Depends on** VOC-1, EDT-1, AI-1, AI-4, DESIGN §5.5

**User story** — As a meeting host, I want to review the recording with its transcript, cut the small talk and export the audio, so that I can share a clean recording or keep it as a record.

**Description**
- The editor (DESIGN §5.5) shows, for `kind: "audio"`, a **waveform per track** (mic, system) instead of the video preview, with the timeline, markers and the caption/transcript panel. Playback, scrubbing, J/K/L and Space work as for video.
- The transcript panel shows lines with speaker names when AI-8 has run ("Linh 00:04:12 — …"); clicking a line seeks. Caption editing, find and replace and glossary (AI-1, AI-6a) work unchanged.
- Trim, cut, split and speed (EDT-1, EDT-2) and AI-4 silence/filler suggestions apply to all audio tracks together.
- **Audio export** (also available for screen recordings, as "Export audio only"): format **M4A** (AAC-LC, 48 kHz, 128 kbps mono or 192 kbps stereo; default) or **WAV** (48 kHz, 24-bit); tracks: Mix (default), Mic only, System only; loudness normalization to −16 LUFS (on by default for M4A); title and date written as file tags. Runs as an `export` job with progress (EXP-4). WAV needs the `wav` muxer and `pcm_s24le` encoder added to the LGPL FFmpeg build (`packaging/ffmpeg/build-macos.sh`). Output in the bundle's `exports/` and optionally a folder.
- Transcript exports (TXT, SRT, VTT from AI-1) gain a **Speaker names** switch (AI-8) and the report exports come from AI-9.

**Acceptance criteria**
- **AC1** Given a 10-minute audio recording, then the editor shows one waveform per recorded track with markers at their times, and Space plays from the playhead.
- **AC2** Given a cut from 01:00 to 01:30, when exporting M4A Mix, then the file is 9:30 ± 1 frame of audio (20 ms), AAC 48 kHz, and its integrated loudness is −16 ± 1 LUFS.
- **AC3** Given Mic only, then the export contains no system audio (cross-correlation with `system.wav` below 0.1).
- **AC4** Given a screen recording, when "Export audio only" runs, then an M4A with the same cuts is produced and no video is encoded.
- **AC5** Given a 60-minute recording on an M-series Mac, then M4A export finishes in ≤ 60 s.

**Edge cases and errors** — No transcript yet → the panel shows Transcribe (AI-1) or the no-model hint. FFmpeg missing → as EXP-1 (`job_failed`, `reason_code`).

**Agent interface** — `export_audio { capture_id, format?: "m4a"|"wav", tracks?: "mix"|"mic"|"system", loudness_lufs?: number|null, out_dir?, request_id? }` → `{ job_id }` → `{ path, size_bytes, duration_s }` (Free). Editing uses the existing tools (`trim`, `cut_segments`, `split`, `set_speed`). CLI `capturemann export <id> --audio [--format wav] [--tracks mic]`.

**As built (Oct 26, 2026, audio export only)** — `cm-media::audio_export` builds the FFmpeg graph with the same cut/stretch/join code as the video export (`edit_plan::audio_graph`, so both apply `edits[0]` and the pause gaps identically) and runs **two-pass `loudnorm`** (pass 1 measures the edited mix, pass 2 applies the measured values in linear mode; it falls back to the single-pass filter if the measurement cannot be read, and skips normalising digital silence). Which audio exists comes from the files in the bundle (`mic.denoised.wav` or `mic.wav`, `system.wav`), not from the capture kind, so audio bundles and screen recordings take one path and no picture is read. Gains and mutes of `set_audio_mix` apply. The daemon runs it as an `export` job with `kind: "audio"` (`cm-daemon/src/export_audio.rs`); the entry in `manifest.exports` has `kind: "audio"` and the preset `audio-<tracks>` (one entry per tracks choice), and the video-only readers (upload's latest export, the player) skip it. `out_dir` must be an existing absolute folder; the copy never overwrites. Tested with fakes (argument-graph unit tests, validation through the daemon) and **with FFmpeg on PATH** (golden tests: duration within 20 ms after a cut, AAC 48 kHz, -16 ± 1 LUFS by `ebur128`, Mic-only correlation below 0.1 with a tone as system track, no video stream for a screen recording). They print `SKIPPED` when the FFmpeg lacks `aac`, `loudnorm`, `wav` or `pcm_s24le`. **Open:** AC5 (the 60-minute timing on an M-series Mac); that the bundled LGPL FFmpeg has the `wav` muxer and `pcm_s24le` encoder (the build script lists them; confirm on the release build, the golden tests print `SKIPPED` without them); the hardware run of `tests/manual/VOC-2.md`. No `verification/` report exists, so this is not "verified".

**As built, UI (Oct 26, 2026, Stage 2; tested with fakes, not checked by eye)** — The editor opens a `kind: "audio"` recording in its own view (`ui/recording_editor/audio_view.rs`; logic in `recedit/voice.rs` and `recedit/audio_export.rs`, unit tested). Board V4: the "now speaking" card (speaker, time since the line began, the line at 20 px with the word under the playhead marked, transport, key hints) replaces the picture; lanes for Markers (white flags with labels), Speakers (coloured blocks, empty without diarization), one waveform per track (Mic, System; peaks come from `cm_media::decode::AudioBank::lane_peaks`, 20 per second, put on the session clock with the pause gaps) and the cuts (hatched grey) and the suggested cuts (hatched amber, with "Suggested cut: ..." under the lanes); the whole-recording strip with the viewport box, marker ticks and the playhead (a click centres the view). Keys: Space, J (back 5 s), K (pause), L (play, then forward 5 s), M (marker through `add_marker` at the recorded time, so pauses are removed and Undo restores), I, O, S, Delete, R, N. The header has Details, Upload (`upload { capture_id }`, default destination) and Export audio...; no Publish. Tab set `audio`: Speed, Transcript (wide, 560 to 600 px), Speakers (AI-8) and Report (AI-9), both built, with the stable ids `re-tab-speakers` and `re-tab-report`; screen recordings get both tabs too, board `set="video"`, Suggestions (cuts only) and Output (length, Export audio..., Upload). The Transcript tab has the language switcher (the original and each file in `translations/`), "Translate..." (a row of language chips that calls `translate_captions`; the result arrives as `translation.ready` and a toast), turns with avatar, name, time chip (a click seeks), an "overlap" chip, marker dividers, the line under the playhead highlighted and followed, and the footer TXT, SRT, VTT (`export_captions` with `language`; the **Speaker names** switch sends `speaker_names` for SRT, VTT and TXT always name known speakers). Board V7: the Export audio sheet (format cards, tracks, loudness switch, the tags line, "Also save a copy to" with the folder picker, the footer with the length after the cuts and the size estimate from the bit rates) calls `export_audio` with an explicit `loudness_lufs`; the result is a toast with the file name, size and loudness, **Show in Finder** and **Upload** (`upload { file }`). "Export audio only" is a button in the Output tab and in the details page's Exports card. **Not yet:** editing transcript lines in the Transcript tab (Captions tab only on screen recordings), the trim handles on the audio lanes (I and O and the toolbar do it), streamed peaks for very long recordings (the whole recording is decoded into memory as for video), AC5 timing. Manual script: `tests/manual/VOC-2.md`. No `verification/` report exists, so this is not "verified".

**Out of scope** — MP3 (needs an extra FFmpeg component; P2), multitrack WAV stems, audio effects (EQ, compression).

**Test notes** — Golden export tests (duration, codec, loudness with `ffmpeg -af ebur128`), the Mic-only isolation check with a fixture whose system track is a tone; manual script `tests/manual/VOC-2.md`.

### VOC-3 Live transcript while recording
**Priority** P2 · **Status** Draft (detail before work starts) · **Crates** cm-ai, apps/overlay

**User story** — As a meeting host, I want to see the transcript appear while we talk, so that I can catch a name or a number immediately and mark moments.

**Summary** — Stream the mic (and system) audio through a small Whisper model (base or small) in 5–10 s windows with VAD (whisper.cpp streaming) into an expandable HUD panel; the final transcript is still made after stop with the user's chosen model (AI-1). Clicking a live line adds a marker there.

**Key criteria (to refine)** — Live text appears within 3 s of speech; CPU under 30% of one machine on an M-series Mac with `base`; never blocks or degrades the recording (drops live windows instead); off by default.
