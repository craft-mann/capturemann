# Quick Capture (QC)

**0.3.6, maintainer decision of Nov 17, 2026** (`specs/plans/release-0.3.6-plan.md`; brought into 0.3.5 and moved back to 0.3.6 the same day). UI name: **Quick Capture**. Design pack: `specs/capturemann-0.3.6-quick-capture/` (local, git-ignored; boards Q036Brief, Q036Panel, Q036After, Q036Presets, Q036Scope). This file is the source of truth for the build; where the pack and this file differ, this file wins. **Preview** (the label under the mark; the bar has no Send feedback button, which stays in About and on the other Preview surfaces; no Settings switch).

QC-2 (one smart crosshair) and QC-6 (pinned presets in the dock) are **not** in 0.3.6; the IDs stay reserved.

**Rules that apply to the whole file**
- **Nothing existing changes.** The five dock tiles, the tray items, the Launcher (its hotkey stays ⌥⇧Space on macOS and Ctrl+Alt+Shift+Space on Windows and Linux) and every shortcut (⌥⇧1 to 4, R, M, L) work exactly as before. Quick Capture adds a way in; it does not replace one.
- **Panel options are separate from Settings.** The option tiles are remembered per kind and apply only to captures started from the panel or from a preset. Settings (CAP-4 "After capture", CAP-5 delay, the recording sheet) keep governing captures started any other way, and the two never overwrite each other.
- **Same actions.** The panel, a preset, the CLI and MCP all call the existing actions (`capture_screenshot`, `start_recording`, long shot, audio recording); there is no second capture path. Confirm rules are unchanged (AGT-2).
- **No telemetry, no network.** Presets are a local file. Send feedback (in About) opens the browser and sends nothing before the click.
- **Language.** All text through `cm_i18n` with Vietnamese entries; brand marks use the theme's text colour (OD-21).

### QC-1 Quick Capture panel
**Priority** P1 · **Status** In progress (built and tested with fakes: the state of the bar, its keys and tooltip texts, the run each kind makes, the shortcut and its conflicts, the Launcher row, the tray item, the bar's size and the two-row rule, the placement, the label widths in English and Vietnamese, AC1 to AC9 and AC16 to AC19 as far as they do not need a screen; the bar, the dock button and the popovers have not been looked at on a screen or run on real hardware, see `tests/manual/QC-1.md`) · **Crates** apps/desktop, cm-core, cm-daemon · **Depends on** CAP-1, CAP-2, CAP-4, CAP-5, CAP-6, REC-1, VOC-1, LNC-1

**User story.** As someone who captures often, I want one slim bar with the kind, the target, the options and one button, so that I do not choose between five tiles and hidden settings every time, and so that it covers a thin strip of the screen instead of a block.

**Description**
- **Layout.** One bar in one row, 60 px high, radius 16, the HUD surface, the same width for Screenshot, Video and Audio so that switching the kind never moves anything. It has icon buttons only, no text labels: each button is 44 px wide and 48 px high, with an 18 px icon and its key in Geist Mono 10 px under the icon. Left to right:
  1. The CaptureMann mark with the **Preview** tag under it (see "Preview").
  2. **Kind**: Screenshot (key 1), Video (2), Audio (3). The selected kind is a raised chip inside a recessed track. The bar opens on the last-used kind.
  3. **Target**, in a second recessed track with the selected one raised. Screenshot: Region (R), Window (W), Display (D), Long Shot (L). Video: Region, Window, Display. Audio has no target: the slot, the same width, holds the microphone level meter. Region and Window use the existing pickers (CAP-1); Long Shot uses CAP-6.
  4. **Options**, four buttons. Screenshot: **Editor** (E, open in editor after capture), **Copy** (C, copy to the clipboard), **Auto-redact** (A), **Delay** (T). Video: **Mic** (M), **System audio** (S), **Webcam** (B), **Countdown** (T). Audio: **Mic** (M), **System audio** (S), **Transcribe** (N), **Markers** (K). An option that is on has a light fill and a dot; a value (Delay, Countdown: "3s") or a menu (the preset) is a small badge in the button's corner. The choices are remembered per kind.
  5. **Preset** (P): opens the preset picker (QC-4); the button shows the menu badge and is on while a preset is picked.
  6. **Action**: 48 px high, the only filled control, with the Enter key. A neutral **Capture** for Screenshot, rec red **Record** with an ink dot for Video and Audio (red still means recording only). With a preset picked its name is a second line under the word.
  7. **Expand/collapse toggle** (O): a small chevron button at the right end, 38 px wide (see "Collapsed bar"). The bar has no Settings button and no Send feedback button; the settings are reached through **Edit presets…** in the preset picker.
- **Size.** On a display narrower than 900 points the bar splits into two rows: kind and target, then options, preset, action and the toggle; the same on any display where the one row would not fit with the gaps at the edges (the one row is 867 px wide). The two rows are narrower and taller; the controls are the same. The two rows are for the expanded bar only.
- **Collapsed bar.** The toggle (or the key O) collapses the bar to a compact form: the mark with the Preview tag, the kind track (1 2 3), the preset (P), the action (Capture or Record) and the toggle, in one row, 60 px high and 463 px wide, the same for every kind and on every display (never two rows). Expanded is the full bar described above. The chevron points left while the bar is expanded (it folds in) and right while it is collapsed. The window keeps its left and top edge where they are and grows or shrinks to the right; where that would leave the display it moves just far enough to be fully on it (on Linux, where the window cannot be moved, it keeps its corner). While the bar is collapsed the controls that are hidden do nothing: R, W, D, L, the option letters, Left and Right are ignored, and a value menu of a hidden option cannot be opened; collapsing with a value menu open closes it. The picker, a value menu and the name screen are placed as before in both states; collapsing or expanding with the picker or the name screen open keeps it open under the bar. The chevron's tooltip and accessible name state the action and the key ("Collapse · key O" while expanded, "Expand · key O" while collapsed), and the control is exposed as expanded or collapsed. The state is remembered in `quick_capture.json` (the field `collapsed`; per user, not per kind), applies when the bar opens, is the bar's own like the options (a picked preset does not change it) and is separate from Settings. A file written before the field existed opens expanded.
- **Popovers.** The preset picker, the menu of a value (Delay, Countdown) and the name screen of "Save current as preset…" open as a popover under the bar, aligned to its right end; the bar stays where it is. Where the display has no room under the bar the popover opens above it (macOS and Windows) or takes the room there is under it and scrolls (elsewhere); it is always fully on the display. The picker has the rows "No preset", every preset (name, a summary line and, for the first four, its Ctrl+1 to Ctrl+4 key), **Save current as preset…** and **Edit presets…**.
- **Tooltips.** Hovering a button or moving the keyboard focus to it shows, after 400 ms, its name, its state ("Countdown · 3 s", "Copy · on"), its key on the bar, and for a kind also the global shortcut as the app has it set (read from the shortcut settings, so a rebound chord shows). The tooltip text is also the control's accessible name, with on, off, selected as the control's state. The window has a strip under the bar for the tooltip so that it is never cut at the window's edge.
- **Opening.** Four ways: (a) the tray or menu-bar menu gets a first item **Quick Capture…** (the native menu stays, CAP-2); (b) a **Capture…** button in the sidebar dock under Record… (not in the narrow rail), a neutral primary button with its keycap; (c) a **Quick Capture** row in the Launcher, Capture group; (d) the global shortcut **⌥⇧C** on macOS and **Ctrl+Alt+Shift+C** on Windows and Linux, shortcut action `open_quick_capture`, rebindable in Settings > Shortcuts and conflict-checked like the others. From the tray the panel opens on the tray icon wherever the system gives the icon's position (the macOS status item and the Windows notification area): centred on the icon, under it when the icon is in the upper half of the display and above it otherwise, always fully on the display; where the system gives no position (Linux) it opens near the pointer; from the shortcut, the dock or the Launcher it opens near the pointer on the display that has it. On X11 the pointer is read from the X server, so the panel opens where the pointer is, never at a fixed place. A Wayland session lets no program read the pointer or place a window: the panel opens centred on the display (the compositor may put it elsewhere, as GNOME does for the first window of an app). The bar is placed as before: the tray icon, the pointer on X11, centred on Wayland, always fully on the display; only its size changed.
- **Moving and edge.** The bar's background is a grip: dragging it moves the bar (the buttons never start a drag). The bar and its popovers are opaque, with a clear edge line, so they read on dark and light desktops.
- **Keys.** Plain keys while the bar is open, ignored when Cmd, Ctrl or Alt is held except the ones named here: 1, 2, 3 switch the kind; R, W, D, L choose the target (Long Shot only for Screenshot; Left and Right still cycle the target); the letters under the options toggle them (Screenshot E, C, A, T; Video M, S, B, T; Audio M, S, N, K; T opens the value menu); P opens the preset picker; O collapses or expands the bar; Ctrl+1 to Ctrl+4 choose the first four presets directly, with the picker open or not; Enter or Space captures or records; Esc closes. While the bar is collapsed only 1, 2, 3, P, O, Ctrl+1 to Ctrl+4, Enter, Space, Esc and Tab work; the keys of the hidden controls are ignored. Tab and Shift+Tab move the focus through the controls with a visible ring; Up and Down step a focused value control (or toggle a focused option). In the picker Up and Down move the highlighted row (a ring shows it, and it stops at the first and the last row), Enter or Space chooses it, and Esc closes the picker only; Esc in a value menu or the name screen also goes back one step first. While the name field of "Save current as preset…" is open it owns the keyboard: plain letters and digits go to the field and never to the bar.
- **Value tiles.** Delay offers Off, 3 s, 5 s and 10 s; Countdown offers Off, 3 s, 5 s and 10 s. A click or its key opens the choices in the popover; picking one or Esc goes back. Defaults on first use: Screenshot Copy on and the rest off; Video Mic on, Countdown 3 s; Audio Mic on. The choices are written to `quick_capture.json` in the settings folder, never to `settings.json`.
- **What each target does.** Screenshot Region: the capture overlay (a frozen frame, the same picker as Option+Shift+1). Window: the window list (R19). Display: the display that has the pointer. Long Shot: the Long Shot picker (CAP-6). Video Region and Window: the pickers in `--pick` mode, then the recording starts after the Countdown; Video Display: the primary display. The panel's Delay tile is the screenshot delay for that capture only. A recording from the panel starts at once (the Record button is the confirmation) and writes none of the Record sheet's remembered choices.
- **Audio options.** Mic and System audio choose the sources. Transcribe starts the transcription of the take when it ends. Markers shows, after the start, the shortcut that adds a marker (Option+Shift+M).
- **Screenshot options.** Editor opens the capture in the editor when it is stored. Copy copies the picture. Auto-redact runs the on-device text reader and blurs what it finds in one undo step before the picture is copied, so the clipboard never holds the unblurred picture. If the reader is not available the capture is kept and a notice says so.
- **The bar and the presets are separate.** What the options show while a preset is picked is the preset's; the options the bar remembers in `quick_capture.json` are the bar's own and are not changed by picking a preset, by changing a tile on top of it or by running a preset from its shortcut. Choosing **No preset** (or changing to another kind's tab) puts the bar's own options back.
- **Countdown.** A recording from the panel uses only the panel's Countdown tile (Video). An audio recording has none and starts at once; the Countdown in Settings is not used.
- **Window behaviour.** The bar stays open until the user closes it (Esc, the shortcut or tray item again, or a capture starting); a click outside it, or another window taking the focus, never closes it, and a click on the bar gives it the keys back. The panel closes as soon as the capture starts, waits 150 ms (`CAPTURE_DELAY_MS`) like the Launcher, and is excluded from screen capture and recording like the HUD where the system has a way to do that (macOS and Windows). **Linux and Wayland have none:** neither X11 nor the xdg-desktop-portal Screenshot and ScreenCast interfaces, nor the compositor protocols GNOME and KDE offer, let a program mark its own window as left out of a capture, so a portal screenshot or a recording started by another program while the panel is open can show it. The app closes the panel before any capture it starts itself, and on Linux it hides its toasts for the capture. Every control has an accessible name.
- **Keyboard on X11.** The panel, the after-capture bar, the edit sheet and the Launcher take the keyboard when they open, even though the window manager never focuses an override-redirect window: the app sets the input focus on them itself and gives it back to the window that had it when they close. The toasts and the recording windows never take it. The bar's keys and the text fields of the sheet work as on the other systems.
- **Preview.** The design has no place for the Preview label, so the bar keeps it in the smallest form: a compact **Preview** tag under the mark at the left end (a tooltip, no popover), inside the 60 px height, in both the expanded and the collapsed bar. The bar has no Send feedback button (maintainer decision of Nov 20, 2026, replacing the earlier requirement of one); Send feedback stays in About and on the other Preview surfaces, and Quick Capture remains a `PreviewFeature` entry in `cm-core/src/features.rs`. No Settings switch.
- **Microphone level (Audio).** The target slot of the Audio kind shows the microphone meter. Without recording, a live level would open the microphone (and light the system's recording indicator) only to draw a bar, so the bar draws the meter unlit; the live level is on the recording sheet and the HUD.
- **Hotkey fails to register.** Settings shows "Couldn't register: used by another app" (as CAP-2.AC3) and the tray item still works.

### QC-3 After-capture bar
**Priority** P1 · **Status** In progress (built and tested with fakes: the decision between the bar and the toast, the place under or above the area and on the display, Undo, the keys; not looked at on a screen or run on real hardware, see `tests/manual/QC-1.md`) · **Crates** apps/desktop · **Depends on** QC-1, CAP-4, ANN-5, CAP-6, REC-1

**User story.** As someone who captures first and decides later, I want a small bar after a screenshot, so that Edit, Copy, Save, Text, Long Shot or Record is one key away.

**Description**
- **When it shows.** After a **screenshot started from the panel or a preset** when both **Editor** and **Copy** are off for that capture. The screenshot is saved to the library first, so no choice loses it.
- **Actions.** **Edit (E)** opens the editor; **Copy (C)** copies the image; **Save (S)** saves to the default folder; **Text (T)** copies recognised text (ANN-5); **Long Shot (L)** extends this area by scrolling (CAP-6, the captured area as the start); **Record (R)** records exactly this area (the countdown, then the normal HUD).
- **Place.** Under the captured area, or above it near the bottom edge of the display, always fully on the display. The area is the rectangle the overlay reports for a Region, the window for a Window, the display for a Display; for a delayed Display capture the display is the primary one.
- **Dismiss.** Esc or a click elsewhere closes the bar; the capture stays in the library. It closes by itself after 20 seconds without the pointer over it, and never while the pointer is over it.
- **Save (S).** Writes the picture into the folder of Settings > General "Save a copy to a folder" when that is on; otherwise it opens Save as. Text (T) is dimmed when no text reader is available. Record (R) records the area with the panel's Video tiles (Mic, System audio, Webcam, Countdown). Long Shot (L) starts CAP-6 on the area with Auto scroll when it is available, else Hand scroll.
- **When Editor or Copy is on.** No bar: the capture goes where the panel says and a toast offers **Edit** and **Undo** for 6 seconds (the toast stays while the pointer is over it); Undo removes that capture from the library without asking, because it was just made.

**Acceptance criteria**
- **AC1** Given a panel screenshot with Editor off and Copy off, then the bar shows the six actions with their keys under the captured area.
- **AC2** Given Editor on or Copy on, then no bar appears, the capture goes there and a toast shows Edit and Undo for 6 s.
- **AC3** Given Esc on the bar, then the bar closes and the capture is in the library.
- **AC4** Given Record (R), then a recording of exactly that area starts after the countdown with the normal HUD.
- **AC5** Given Undo on the toast, then the capture is removed from the library.
- **AC6** Given the pointer over the bar, then it does not close by itself.
- **AC7** Given a capture near the bottom edge, then the bar is above the area and fully on the display.

### QC-4 Presets
**Priority** P1 · **Status** In progress (built and tested with fakes: the model, `presets.json`, the starters, the daemon actions, the picker's choices, the shortcut conflict check against every global shortcut and every other preset, the Save to folder with the local date, Auto-redact and the editor tool after a capture, the Launcher and tray entries, Settings > Capture > Presets and the edit sheet, AC1 to AC7 as far as they do not need a screen; not looked at on a screen or run on real hardware, see `tests/manual/QC-1.md`) · **Crates** cm-core, cm-daemon, apps/desktop · **Depends on** QC-1

**User story.** As someone who repeats the same setup, I want to save it with a name, so that one pick (or one shortcut) does it.

**Description**
- **A preset holds:** name; kind; target (Region, Window, Display or Long Shot; never the area itself); the kind's option tiles; where to save (a folder, with `{date}`); what to do after (open the editor with a chosen tool, copy, or nothing); an optional shortcut.
- **Storage.** `presets.json` in the app's settings folder, so a team can share one file. Unknown fields are kept when saving. An invalid preset in a hand-edited file is skipped and one notice names it; the others still load.
- **Where they show.** The preset picker, a popover under the Quick Capture bar (No preset, the presets with a one-line summary, **Save current as preset…**, **Edit presets…**); the Launcher ("Preset: {name}"); the tray menu; Settings > Capture > Presets (reorder, edit, delete).
- **Edit sheet.** Name; kind and target; toggles Copy to clipboard, Auto-redact, Open in editor; Then (a tool); Save to; Shortcut with Change; Save preset, Cancel, Delete.
- **Shortcut.** A preset's shortcut runs it directly; it is conflict-checked with every other shortcut.
- **What the app does after a capture.** A call to `capture_screenshot` or `start_recording` carries what a call can carry (QC-5); the app does the rest through the existing actions: Auto-redact (`suggest_redactions`, then one `annotate` with the blur), the editor and its tool, the folder (the rendered picture is written there in the preset's format; scale 2 keeps the capture's pixels, scale 1 writes half the width and height), and transcribing after an audio take (`transcribe`). A screenshot preset's `cursor` is kept in the file and shown nowhere: no capture action takes it today. A preset's `markers` (audio) is the panel's Markers tile.
- **Where they show, in the app.** The picker in the panel; the Launcher rows "Preset: {name}" (the shortcut of the preset on the row); the tray's **Presets** submenu (after Recent captures); Settings > Capture & recording > Presets at the top of the page, where **Edit presets…** in the panel's picker leads. A preset's Delete there asks for a second click. A preset picked in the panel keeps its tool, folder, format and scale while the tiles are changed; changing the tab to another kind drops it.
- **Shortcut.** A preset's shortcut is registered as a global hotkey where the desktop lets an app have global keys (not on a Wayland session without the portal). The sheet records it with Change: a chord that a global action or another preset already has is refused with that owner named ("Already used by Capture region", "Already used by the preset Bug report"); and a global action cannot take a chord a preset has. A hand-edited file that gives two presets one chord, or a preset a global action's chord, keeps the first and registers no second one.
- **Sheet size.** The edit sheet is never taller than the display leaves, and it fits a 1080p display at 150 % scale (1280 by 720 logical px). The title and the footer (Delete, Cancel, Save preset) stay in place and never cover a field; the rows between them scroll, with a scrollbar as the cue, and every row, Shortcut included, can be reached by scrolling.
- **Starter presets** (editable and deletable; deleting one does not bring it back): **Bug report** (Region, copy, Auto-redact, then the step badge tool), **Docs shot** (Window, editor, cursor shown, PNG at 2×), **Demo video** (Display, mic, webcam, 3 s countdown), **Meeting** (Audio, mic and system, transcribe after).

**Acceptance criteria**
- **AC1** Given the picker, when "Bug report" is chosen, then kind, target and option tiles are filled and the action bar reads "Capture · Bug report".
- **AC2** Given Save current as preset, then a preset with the panel's current setup appears in `presets.json` and in the picker, and reading the file back gives the same setup.
- **AC3** Given a `presets.json` with an unknown field, when a preset is saved, then the unknown field is still in the file.
- **AC4** Given a hand-edited `presets.json` with one invalid preset, then only that preset is skipped and one notice names it.
- **AC5** Given a preset with a shortcut, then the shortcut runs it directly; a shortcut already used by another action is refused with the conflict named.
- **AC6** Given the four starters deleted, then they do not come back on the next start.
- **AC7** Given a preset with Save to `~/Bugs/{date}`, then the capture is saved there with the local date and also appears in the library.
- **AC8** Given the picker is opened, then the popover is as tall as its rows need (a preset row is about 55 px high: the name line, the summary line, padding and border), up to the room the display leaves, and no row is cut off; beyond that height the list scrolls and the highlighted row is scrolled into view; every row has an accessible name with the preset's name and summary, and the chosen preset is marked selected.

- **AC10** Given the edit sheet opened for an existing preset, then its Name field shows the preset's name.
- **AC9** Given the edit sheet on a display 720 px tall in logical px, then the footer buttons do not overlap any field, the Save to folder and Shortcut rows are reached by scrolling the body, and a scrollbar shows that the body scrolls.

### QC-5 Presets for agents and the CLI
**Priority** P2 · **Status** In progress (built and tested with fakes, AC1 to AC6; no run on real hardware yet) · **Crates** cm-daemon, cm-mcp, cm-cli · **Depends on** QC-4, AGT-2

**User story.** As someone who uses an AI agent, I want the agent to run my preset by name, so that it captures the way I do.

**Description**
- `capture_screenshot` and `start_recording` take an optional `preset` (the name or the id). A new read-only tool **`list_presets`** (Free) returns the presets. CLI: `capturemann capture screenshot --preset "Bug report"`, the matching argument on the record command, and `capturemann presets list`.
- An explicit argument in the same call wins over the preset's value.
- **Confirm rules are unchanged:** a preset that records still needs the on-screen confirmation, and the dialog shows the plan the preset resolves to. A preset cannot loosen a locked tool or change `agents.tool_policy`.
- A preset holds no area, so a call that uses one still gives `target`. The CLI is the exception: `--preset` alone captures the primary display, and a Window preset asks for `--window`. A screenshot preset does not fit `start_recording` and a video or audio preset does not fit `capture_screenshot`; the call fails with `invalid_input`.
- The preset is written into the call's parameters before the call is checked, so the tier, the user's per-tool setting and the confirmation see an ordinary call. A preset sets only what the call itself can carry (delay, copy, Long Shot mode; microphone, system sound, webcam, cursor, frame rate and countdown); Auto-redact, the editor, the folder and the tool are for the app.
- `start_recording` already had `preset` for the five audio use cases (`room`, `online`, `lecture`, `product`, `note`). With `mode: "audio"` those five words keep that meaning; any other value is a Quick Capture preset.
- Agents read presets (`list_presets`) and run them; saving, deleting and reordering presets are internal actions for the app and are refused for agents.
- An unknown preset gives `invalid_input` naming it. `docs/reference/` is regenerated (`docs/reference/gen_agent_reference.py`) and the tool-count assertion in `crates/cm-mcp/tests/stdio.rs` becomes 90.

**Acceptance criteria**
- **AC1** Given `capture_screenshot { preset: "Bug report" }`, then the result equals the same call with the preset's options written out.
- **AC2** Given `list_presets`, then it returns every preset with its name, kind and target, and writes nothing.
- **AC3** Given `capture_screenshot { preset: "Bug report", delay_s: 3 }`, then the delay is 3 s and the other options come from the preset.
- **AC4** Given a recording preset started by an agent, then the confirmation dialog appears and shows the resolved plan.
- **AC5** Given `preset: "nope"`, then `invalid_input` names it.
- **AC6** Given the CLI `--preset "Bug report"`, then it behaves as AC1.
- **AC7** Given `capturemann record start --preset <a screenshot preset>`, then it fails with `invalid_input` before it prints "Waiting for confirmation" and before any confirmation is asked.

**Agent interface** — as above; both tools keep their tiers (Free for screenshots, Confirm for recording).

**Out of scope** — QC-2 smart kind, QC-6 pinned presets in the dock, a preset for Click Guide, shared preset folders.
