# AI (AI)

Local-first: every AI feature runs offline by default. Release 0.2.0 has one text model, the engine built into CaptureMann (AI-7), and no API keys or remote providers; nothing leaves the machine. Using a server the user runs, or a provider with the user's own key, is on the backlog, marked *later* (AI-7, "Later (backlog)"). All AI features are free. Suggestions are never applied without the user or agent accepting them.

**Provider model (`cm-ai`)**
- `Transcriber`: `whisper-rs` (whisper.cpp) with downloadable models: `base` (~150 MB, default on 8 GB machines), `small` (~500 MB, default on 16 GB+), `medium` (optional) and `large` (large-v3, about 3.1 GB, for powerful Macs). **Model table as built (Oct 24, 2026; the models are whisper.cpp's ggml files from Hugging Face, pinned in `crates/cm-ai/data/models.json`):** the memory a model needs while it runs is the whisper.cpp README's figure (https://github.com/ggml-org/whisper.cpp: tiny ~273 MB, base ~388 MB, small ~852 MB, medium ~2.1 GB, large ~3.9 GB), kept in the catalogue as `ram_mb` and shown on each model card; the download sizes come from the files (the README's disk column is in MiB: 75, 142, 466 MiB and 1.5, 2.9 GiB; the app shows MB). `list_models` adds `ram_mb` to each model (additive). The 16 GB figure in this file is the default for automatic transcription, not what a model needs. Models are downloaded on first use with consent and a size notice; checksum verified. **Maintainer decision (Oct 22, 2026): there is no download on first use.** The user chooses and installs models from a dedicated AI page of the app (and `capturemann ai models`, MCP `download_model`): list with size and a one-line hint, Download (explicit, with progress, resumable, cancellable), Import from a file, Use by default, Remove. While no model is installed the app shows a gentle notice that a model is needed to transcribe, and nothing is fetched unasked; the automatic transcription after a recording (setting `ai.auto_transcribe`, default on with 16 GB RAM or more) does nothing without an installed model. Models for AI-2 are added later, when AI-2 needs one.
- `TextModel`: specified in AI-7. Since the maintainer decision of Oct 27, 2026 the only provider in 0.2.0 is the **built-in engine** (provider `embedded`: llama.cpp's `llama-server` as a helper program inside the app, with GGUF models the user downloads on request), or `none`; a user-chosen local server and a remote provider with the user's key are backlog items (*later*).
- Every AI job is a background job (AGT jobs) with progress.

### AI-1 Transcript and captions
**Priority** P0 · **Status** In progress (engine built Oct 22, 2026 and tested with fakes: the model store with user-started downloads, the whisper.cpp transcriber, `transcript.json`, caption lines, SRT, VTT and plain-text (TXT, optional timestamps) export, the mapping through cuts and speed (AC4), re-generating a transcript (replaces it, keeps the caption edits whose words are heard again and drops the rest as one undoable revision (AI-6a), keeps the old one when a run fails or is cancelled); the daemon, MCP and CLI surface is built and wired to the real adapters (`cm_daemon::ai_engine`) and tested end to end with a scripted transcriber: model list, explicit download as a confirmed job with progress and cancel, import, select, remove, `transcribe` as a job with the `no_model` error, `get_transcript`, undoable `set_captions`, `export_captions`, the app-only setting `ai.auto_transcribe`; real models have run on the maintainer's Mac (small and medium, reported by the maintainer; a 5 s synthetic clip transcribes at about 15x real time with small), but AC1 (word error rate) and AC2 (a 10-minute recording) are not measured; the desktop UI is built and tested against a scripted daemon, untested by eye: the AI page with the model manager, the "no model yet" notice, the Transcribe entries, the caption editor and SRT/VTT buttons; not built: burned-in captions (AC5); burned-in captions and the `set_caption_options` show/hide switches are built, see "As built, burned-in captions" below) · **Crates** cm-ai, cm-render · **Depends on** AUD-1, EXP-1

**User story** — As a creator, I want an accurate transcript and captions made on my machine, so that my videos are accessible and searchable without paying for a service.

**Description**
- Transcribe the mic track (denoised if available; system audio optional) with word-level timestamps; language auto-detected or set by the user (99 Whisper languages).
- Stored as `transcript.json` (words with start/end `MediaTime`, confidence) in the bundle; edits to cuts/speed are applied when exporting captions.
- Caption editor: a list of caption lines (max 42 characters per line, 2 lines, 1–7 s each) editable in place; clicking a line seeks the preview. **As built (R3c, Oct 24, 2026; plan `specs/plans/caption-editor-plan.md`, tested with fakes; the maintainer saw it by eye and called it good, as reported):** Captions mode widens the inspector to 600 px; one row per line with start and end time and the full text edited in place; the line under the playhead is highlighted and followed; Split (at the text cursor, middle word at either end), Merge with next and Remove under the field being edited and as hover icons; Enter commits and opens the next line, Shift+Enter adds a line break, Cmd/Ctrl+Enter splits, Up/Down move between lines, Esc ends editing; a play button plays just that line; Cmd/Ctrl+F finds and replaces (Vietnamese-exact, NFC-equal, Replace all is one undo step); a captions lane on the timeline is synced with the rows; SRT, VTT and TXT with the timestamps switch sit in the panel footer. Not built: the board's timeline zoom range.
- Exports: SRT and VTT files, plain text (`.txt`, `<title>.txt`: one caption line per row, optional `[mm:ss]` timestamps; edited lines win and cuts and speed apply like the other formats) for other uses, and optional burned-in captions (style: Inter 600, white on 60% black box, bottom safe area; size scales with export height).
- *As built, burned-in captions:* two switches per recording, set with `set_caption_options { enabled?, burn_in? }` (one undoable revision, Free): `enabled` shows the captions on the video in the editor's preview, `burn_in` is whether exports burn them in by default; `export_video { captions: "burn" | "none" }` overrides it (`burn` fails with `not_found` and the way to get captions when there is no transcript; the recording's default alone never blocks an export, it exports without captions and the job result says `captions: "skipped_no_transcript"`). Lines are the user's edited ones, else built from the transcript, with the edit list applied (AC4). They are drawn by the compositor: Inter (the Regular file, thickened to read as weight 600: no SemiBold file is bundled), white on a rounded 60% black box, size 4.5% of the output's **shorter side** (the height on landscape, the width on 9:16, where 4.5% of the height wrapped a normal line into five rows), centered, wrapped to two rows. The safe area comes from the output's aspect: 16:9 keeps 6% clear at the bottom, 1:1 12%, 9:16 the bottom 20% and the right 12% (AC5). With a background and padding the caption stays inside the screen picture, not on the background around it; a caption that would cover the camera bubble slides into the free side of it, or sits above it when it fits on neither side. GIF and WebM burn captions too. CLI: `capturemann ai captions options <id> [--show|--hide] [--burn|--no-burn]` and `capturemann export <id> --burn-captions|--no-captions` (`--captions srt|vtt` keeps writing a caption *file*).
- *As built, the captions UI (untested by eye):* the Captions card in the recording editor and the Transcript section of the details page both have "Show captions in the preview" and "Include in exported video" switches (`set_caption_options`, one undoable revision each). The preview draws the caption track from the same function the export uses, rebuilt only when the switch, the saved lines, the transcript or the edit list change. The **first** transcript of a recording turns the preview captions on and leaves burn-in off (the maintainer opts in to burning); it never changes a choice the user made (a switch named in `set_caption_options`, even to the value it had, or edited caption lines: the `options_set` marker in the manifest's `captions` object) and it is not a revision, so there is no extra undo step. "Export MP4" (and "Export again") on the details page and in the editor's Output card have a "Burn in captions" tick, shown when the recording has a transcript and starting at the recording's own setting; the result toast says whether the captions were burned in or left out.
- Auto-transcribe after recording: setting, default on when the machine has ≥ 16 GB RAM.
- *Models (maintainer decisions, Oct 22, 2026):* the engine is whisper.cpp through a Rust binding. The user chooses the model in a dedicated AI area of the app (not in Settings); the choices are `tiny`, `base`, `small` and `medium` (about 78, 148, 488 and 1534 MB), each with a one-line hint. **Nothing is downloaded silently**: a model is fetched only when the user (or an agent, after a confirmation) asks, with progress, cancel and resume, and is checked against its SHA-256. A model file the user already has can be imported. While no model is installed the app shows a gentle notice, and `transcribe` fails with `invalid_input` and `data.reason = "no_model"`. Models live in `<config dir>/ai/models`; the list (URLs pinned to a Hugging Face commit, checksums, sizes) is data and a `<config dir>/ai/catalog.json` replaces it.
- *As built:* word times come from the token timestamps; sound descriptions such as `[BLANK_AUDIO]` and `(music)` are dropped; the mic track is used (a denoised copy when the manifest names one), system audio is mixed in only on request or used alone when there is no mic; times are converted to session time through the pause gaps; captions for an export are built from the words that survive the edit list, so cut content is never referenced and words spoken in a segment sped up beyond 2x without "keep audio" are left out.
- *UI as built (desktop, OD-14):* AI is its own sidebar section. Models are listed with size and a speed-vs-accuracy hint; the user presses Download (then confirms the size) or imports a file, selects the one in use, and can remove one; a cancelled or failed download resumes from its partial file. **Nothing is ever downloaded silently**: no model installed shows a quiet, dismissible notice (the AI page, a hint under the Recordings header) and a disabled Transcribe button with the reason. The Captions card of the recording editor lists the lines (a click seeks the preview), edits text in place (wrapped at 42 characters, 2 rows, flagged outside 1 to 7 s, never silently cut), adds a line at the playhead, splits, merges and removes lines, and saves with `set_captions`. The caption lines come from `get_captions` (an action the contract table does not list yet; the UI falls back to building lines from `get_transcript` words when it is missing).

**Acceptance criteria**
- **AC1** Given a 10-minute English fixture with a reference transcript, then word error rate ≤ 12% with the `small` model.
- **AC2** Given a 10-minute recording on an Apple M-series 16 GB machine, then transcription with `small` finishes in ≤ 5 minutes.
- **AC3** Given network disabled, then AI-1 works end to end.
- *Details page and re-generate (Oct 22, 2026, maintainer feedback):* the recording details page shows the stored transcript whenever there is one (language, model, word count, when it was made, read again when the page opens and after a transcript or a revision) with Open captions, Download TXT / SRT / VTT, a Timestamps switch for TXT and Re-generate. Re-generate is a second `transcribe`: it chooses the model for this run (default the active one) and the language (auto by default), and replaces `transcript.json` only when the new run finishes (a failed or cancelled run leaves the previous transcript and your caption edits untouched). Caption lines the user edited belong to the old transcript; since AI-6a (Oct 24, 2026) a successful re-generate keeps an edit where the same words are heard again and drops the others, as ONE undoable revision (`undo` brings the previous captions back); the panel says so before it starts, and the toast after the run says how many edits were kept and how many could not be. (Before AI-6a every edit was discarded.) The keep rule: an edited line is a stored line whose text differs from the lines built from the OLD transcript; it is kept on a new automatic line that overlaps it by at least 50 % of the shorter span and whose automatic text equals the old automatic text of that line; merged, split and hand-added lines cannot be matched one to one and are dropped (`cm_ai::reapply`). The `transcribe` result and the `transcript.ready` event carry `reapplied`, `dropped` and `glossary_replaced`. No transcript yet: the Transcribe button and the gentle no-model hint.
- **AC4** Given a cut from 01:00 to 01:10, then exported SRT timings after the cut are shifted by −10 s and no caption references cut content.
- **AC5** Given burned-in captions on a 9:16 export, then captions stay inside the platform safe area (bottom 20% clear of TikTok UI, see EXP-2).

**Edge cases and errors** — No speech detected → transcript empty with a note; model download fails → retry with resume; `job_failed` with reason.

**Agent interface** — MCP `transcribe { capture_id, language?: "auto"|code, model?: "base"|"small"|"medium" }` → `{ job_id }` → transcript (Free). Resource `capturemann://capture/{id}/transcript`. `export_captions { capture_id, format: "srt"|"vtt" }` → path. CLI `capturemann ai transcribe <id>`, `capturemann export <id> --captions srt|burn`.

**Out of scope** — Speaker diarization (AI-8), caption translation (AI-5).

**Test notes** — WER test with fixtures in 3 languages (English, Vietnamese, Spanish); performance test on reference machines.

### AI-2 Title, description, chapters and tags
**Priority** P1, **after v0.1** (moved out of v0.1 on Oct 24, 2026: the maintainer does not want API keys or a text model in the first release) · **Status** Deferred (not started; the notes below keep the design for later) · **Crates** cm-ai, cm-publish · **Depends on** AI-1, PUB-2

**Review notes (Oct 24, 2026, for when this is picked up)**
- The spec's "local by default" needs a text-generation backend that does not exist yet (cm-ai has Whisper only). Superseded (Oct 27, 2026): the text backend is the built-in engine of AI-7 (a multi-GB model download on request); an OpenAI-compatible endpoint provider is a backlog item (*later*).
- Chapters: the code picks candidate boundaries from pauses and length (first at 00:00, each at least 10 s) and the model only titles them; store chapters as data in source time and write the description text at publish time, so a later cut cannot leave wrong times (AC4).
- v0.1-scope platform would be YouTube only (TikTok and Facebook are deferred); keep the schema extensible.
- With a cloud provider the transcript text leaves the Mac: make the action Confirm for agents when the provider is not local; show "What will be sent" (AC3).
- UI: "Suggest with AI" on the Publish page, three title options, editable chapters, a "Text model" section on the AI page with a Test button.
- Agents can already read `get_transcript` and write metadata themselves through `publish_video`, so v0.1 is not blocked.

**User story** — As a creator, I want titles, descriptions, chapters and tags written from my transcript, so that publishing takes seconds and my videos are discoverable.

**Description**
- Input: transcript (after cuts), capture title, optional user notes ("audience: beginners", "tone: friendly") and the target platform.
- Output per platform (respecting PUB limits): YouTube title ≤ 100 chars, description ≤ 5,000 chars with chapters (first at 00:00, at least 3 chapters, each ≥ 10 s) and 5–15 tags; TikTok caption ≤ 2,200 chars with hashtags; Facebook title + description.
- Three title options to pick from; everything editable before publishing.
- Prompt and output schema are versioned files in `cm-ai/prompts/`; the model must return JSON matching the schema, validated, with one automatic retry on invalid output.
- Provider: local by default; "Use `<provider>`" toggle when a key is configured.

**Acceptance criteria**
- **AC1** Given a 10-minute tutorial transcript, then output validates against the schema and YouTube chapters start at 00:00 with ≥ 3 entries ≥ 10 s apart.
- **AC2** Given network disabled and a local model available, then generation works.
- **AC3** Given the user's API key provider selected, then only the transcript text and user notes are sent (no media), shown in a "What will be sent" note.
- **AC4** Given generated chapters and a later cut, then chapter times are recomputed on export.

**Edge cases and errors** — No local model and no key → button shows "Set up AI" linking to the AI page. Model returns invalid JSON twice → `job_failed` "Couldn't generate — try again or switch model".

**Agent interface** — MCP `generate_metadata { capture_id, platform, notes?, provider?: "local"|"key" }` → `{ titles[], description, chapters[], tags[] }` (Free). An agent can also skip this and write metadata itself. CLI `capturemann ai metadata <id> --platform youtube`.

**Out of scope** — Thumbnail generation (P2).

**Test notes** — Schema validation tests; golden prompts with a stub model; manual quality review on 5 sample videos.

### AI-3 Auto-zoom suggestions
**Priority** P1 · **Status** In progress (the algorithm is built in `cm_ai::suggest::zoom` and tested with synthetic cursor logs for AC1 to AC3 and the no-telemetry error; the `suggest_zooms` action, tool and `capturemann ai suggest zooms` are built and wired to the real adapters (`cm_daemon::ai_engine`) and tested end to end with a scripted transcriber, accepting a suggestion is `set_zooms`; the editor's "Suggest zooms" list with Accept, Accept all and remove is built and tested against the real daemon, untested by eye; the AC1 fixture `dwell_3.jsonl` is generated in the tests, not stored) · **Crates** cm-ai (deterministic, no ML) · **Depends on** REC-7, EDT-4

**User story** — As a creator, I want zooms suggested where I paused or clicked, so that my demo is easy to follow without placing every zoom by hand.

**Description**
- Deterministic algorithm on cursor telemetry (adapted from OpenScreen, MIT, with attribution in `NOTICE`):
  - Dwell: cursor stays within 2% of the frame for 450–2,600 ms → candidate centered on the dwell.
  - Click: a click not inside a dwell → candidate centered on the click, 1.5 s long.
  - Candidates closer than 1.8 s merge (keep the stronger); max 1 suggestion per 6 s of video.
  - Scale 1.8× by default; focus clamped so the zoomed view stays inside the frame.
- Output: suggestions shown dashed on the zoom lane (EDT-4) until accepted.
- *As built (Oct 22, 2026):* `cm_ai::suggest::suggest_zooms(log, edits, gaps, opts)` returns `ZoomSuggestion`s in session time; `zooms_params` builds the `set_zooms` call that accepts them. Rules as specified, with these readings: the 2% box is 2% of the frame on each axis; a pointer parked longer than 2.6 s is not a dwell (its clicks still count); a dwell zoom is the dwell plus 0.4 s (the ease) on each side, centred in time on the dwell; "1 per 6 s of video" is a total cap of `floor(output seconds / 6)`, at least 1, strongest first (a dwell beats a click); regions are clipped to what the edit list keeps (cuts, pauses) and dropped under 0.8 s. The code is an independent implementation of these rules, not a copy of OpenScreen, so it needs no `NOTICE` entry yet.

**Acceptance criteria**
- **AC1** Given the telemetry fixture `dwell_3.jsonl` (three dwells of 1 s), then exactly 3 suggestions are produced at the dwell centers (± 50 ms).
- **AC2** Given two clicks 1 s apart, then one suggestion results.
- **AC3** Given suggestions, then nothing changes in the edit list until accepted.

**Edge cases and errors** — No telemetry (cursor not recorded) → `invalid_input` "This recording has no cursor data".

**Agent interface** — MCP `suggest_zooms { capture_id, max?: n }` → zoom list (Free, not applied); apply with `set_zooms`.

**Out of scope** — Content-aware zoom from on-screen text (P2).

**Test notes** — Deterministic fixture tests.

### AI-4 Silence and filler-word removal suggestions
**Priority** P1 · **Status** In progress (the algorithms are built in `cm_ai::suggest::{silence, filler}` and tested with synthetic audio and scripted transcripts for AC1 to AC3, the minimum and level options, the screen-activity heuristic and recording pauses; the suggestions of fillers need the AI-1 transcript, the `suggest_cuts` action, tool and `capturemann ai suggest cuts` are built and wired to the real adapters (`cm_daemon::ai_engine`) and tested end to end with a scripted transcriber (silence always, fillers when a transcript exists), accepting is `cut_segments`; the editor's "Suggest cuts" list is built (Accept sends one merged `cut_segments`, one undo step, tested against the real daemon, untested by eye); the real screen-activity source is not built) · **Crates** cm-ai · **Depends on** AI-1, EDT-1

**User story** — As a teacher, I want long pauses and "um/uh" suggested for removal, so that my lessons are tight without manual editing.

**Description**
- Silence: mic level below −40 dBFS (configurable) for ≥ 1.2 s (configurable 0.5–5 s) → suggest cutting it down to 0.4 s (keep breathing room).
- Filler words from the transcript: per-language list (English: um, uh, erm, "you know" when isolated…; Vietnamese: ờ, à, ừm…), only when isolated with ≥ 150 ms gaps around them.
- Suggestions appear as amber ranges on the timeline with a count ("23 pauses, 41 fillers — remove 3 min 12 s"); accept all, accept by type, or click individually.
- Applying suggestions creates normal cuts (EDT-1), one undo step.
- *As built (Oct 22, 2026):* `silence_cuts` (PCM from `decode_mono_f32`, 20 ms frames, threshold = the configured level or 6 dB above the 10th-percentile noise floor, whichever is higher and at most -20 dBFS; keeps 0.2 s on each side of a pause, so a 2 s pause removes 1.6 s), `filler_cuts` (whole-token match after folding case, punctuation and stretched letters; English `um uh uhm erm er` and the phrase `you know`, Vietnamese `ờ ờm ừm à`; no list for other languages; 150 ms gap on each side; 30 ms pad), `merge_cuts` (drops a filler inside a pause, removes what is already cut, clips to the kept range), `CutSummary::label` ("23 pauses, 41 fillers, remove 3 min 12 s") and `cuts_params` (one `cut_segments` call). The screen-activity rule is `drop_active` with a `ScreenActivity` source (more than 5% of pixels changed, `frame_diff_fraction`); decoding the screen to feed it is not built.

**Acceptance criteria**
- **AC1** Given a fixture with 10 silences of 2 s, then 10 suggestions each removing 1.6 s.
- **AC2** Given "Accept all", then cuts are applied as one undo step and A/V stays in sync.
- **AC3** Given a filler inside a word ("umbrella"), then it isn't suggested.

**Edge cases and errors** — Screen activity during silence (e.g. the user is typing code silently): suggestions skip silences where the screen changed more than 5% of pixels, unless "Include silent screen activity" is on.

**Agent interface** — MCP `suggest_cuts { capture_id, silence_db?, min_silence_s?, fillers?: true }` → ranges with type (Free, not applied); apply with `cut_segments`.

**Out of scope** — Removing repeated takes ("let me say that again", P2).

**Test notes** — Fixture tests; screen-activity heuristic unit test.

### AI-5 Transcript and caption translation
**Priority** P1 (raised from P2 on Oct 26, 2026, maintainer request; targeted for the next release) · **Status** In progress (Stage 3 backend built Oct 26, 2026, tested with fakes: Whisper to English, the stored translations, the actions, MCP and CLI; the text-model engine, the editor language switcher, burned-in and YouTube tracks are not built; see "AI-5 as built" below) · **Crates** cm-ai, cm-daemon, apps/desktop · **Depends on** AI-1, AI-6a, AI-7 (for targets other than English), PUB-2 (caption tracks)

**User story** — As a creator or meeting host, I want my transcript and captions translated, so that a Vietnamese lesson gets English captions, an English meeting gets Vietnamese notes, and viewers worldwide can follow.

**Description**
- **Two engines, chosen automatically (the user or agent can override):**
  - **Whisper → English.** When the target is English and the source is not, re-run Whisper with the *translate* task on the same audio. Needs **large-v3** (or medium/small, lower quality): **large-v3-turbo was not trained for translation and returns the source language, so it is never used for this task.** No text model needed, fully offline.
  - **Text model → any language.** For every other pair (and for English when the user prefers it), translate the caption lines with the AI-7 text model, line by line in batches with the surrounding lines as context, keeping each line's start and end times. Glossary terms (AI-6a) are passed as "keep as written" unless the glossary gives a translation.
- **Output.** `translations/<lang>.json` in the bundle: `{ language, engine, model, created, lines: [{ start, end, text }], edited }`. Whisper-translate output is segmented into lines with the AI-1 rules (42 characters × 2 rows, 1–7 s). Text-model output keeps the source line times; a translated line longer than the limits is re-wrapped, then split in two at a word boundary with the time divided by character count.
- **Editing.** The caption editor gets a language switcher (Original · each translation). Edits to a translation are stored like caption edits (AI-6a) and survive a re-translate when the source line is unchanged.
- **Exports and publishing.** SRT, VTT and TXT per language; burned-in captions use the language chosen in the export sheet; PUB-2 uploads one caption track per selected language to YouTube.
- **Model catalogue additions (with this feature):** `large-v3-turbo` (about 1.6 GB; the recommended speech model since Oct 27, 2026 (the maintainer found its transcription quality good; `small` stays the choice for 8 GB Macs); label "Recommended: fast and accurate for most recordings. Not for translation.") and `large-v3` (about 3.1 GB; label "Best accuracy and translation to English"). Same download rules as AI-1 (explicit, checksummed, resumable). When translation to English is requested and the active model is turbo, the job uses `large-v3` if installed, else `medium`, else fails with `invalid_input` and `data.reason = "translation_model_missing"`.
- **Language detection.** The source language is the transcript's (`transcript.language`); a mixed-language recording translates line by line and leaves lines already in the target language unchanged.

**Acceptance criteria**
- **AC1** Given a 2-minute Vietnamese fixture with `large-v3` installed and the network off, when translating to English, then `translations/en.json` exists, its lines meet the AI-1 line rules, and a reviewer rates at least 90% of lines as conveying the source meaning (manual check, `tests/manual/AI-5.md`).
- **AC2** Given the active model is `large-v3-turbo`, when translating to English, then the job runs with `large-v3` (or `medium`) and the result names that model; with neither installed it fails with `translation_model_missing` and nothing is downloaded.
- **AC3** Given an English recording and a local text model (AI-7), when translating to Vietnamese, then every translated line has exactly its source line's start and end times (or a split of them), and no network request leaves the machine (NFR-9).
- **AC4** Given a glossary term "CaptureMann", then it appears unchanged in every translated line that contains it in the source.
- **AC5** Given the user edited a Vietnamese line, when re-translating after an unrelated source edit, then the edited line is kept.
- **AC6** Given translations for EN and VI, when publishing to YouTube with both selected, then two caption tracks are uploaded with the right language codes.
- **AC7** Given a remote text model provider (AI-7), when an agent calls `translate_captions`, then a Confirm dialog shows the provider and "Caption text will be sent to <host>" before anything is sent.

**Edge cases and errors** — No transcript → `not_found` with the way to transcribe; no text model configured for a non-English target → `invalid_input` with `data.reason = "no_text_model"`; model output that drops or merges lines → retried once per batch, then those lines keep the source text and are flagged `untranslated` (count in the result).

**Agent interface** — `translate_captions { capture_id, target_language, engine?: "auto"|"whisper"|"text_model", request_id? }` → `{ job_id }` → `{ language, engine, model, lines, untranslated }` (Free with Whisper or a local text model; **Confirm** with a remote provider, AI-7). `get_captions`, `set_captions`, `export_captions` and `replace_in_captions` take an optional `language` (additive; default the original). Events `translation.ready`. CLI `capturemann ai translate <id> --to vi [--engine whisper|text-model]`.

**AI-5 as built (Stage 3, Oct 26, 2026; tested with fakes, no real Whisper run, no network; the model checksum below is still to be pinned).**
- **Engine and model choice** (`cm_ai::translate`): `auto` picks Whisper for an English target and the text model for every other target; `whisper` is English only; `text_model` always needs the provider. The text-model engine is **not built**: the seam is the `TextTranslator` trait (`translate_with_text_model` does the batches of 20 lines with 3 lines of context, one retry per batch, `untranslated` flags and the re-wrap and split of long lines) and the daemon's `TranslateService::text_model`, which answers `invalid_input` with `data.reason = "no_text_model"` until AI-7 plugs in. A target equal to the recording's language (`pt-br` equals `pt`) fails with `data.reason = "same_language"`. Model for Whisper: the named model must translate; else the active model when it can (small and base work, with lower quality); else (turbo active or nothing active) `large-v3`, else `medium`, else `invalid_input` with `data.reason = "translation_model_missing"`. `large-v3-turbo` is never used (the Whisper wrapper also refuses it). Nothing is downloaded.
- **Whisper translate task** (`Transcriber::translate_to_english`, `WhisperTranscriber`): the same audio and the same session-time mapping as `transcribe`, `set_translate(true)`, the spoken language as the hint; the output is cut into lines by the AI-1 rules.
- **Stored translation**: `translations/<lang>.json` is `{ version, language, engine, model, created, lines, edited }`; each line is `{ start, end, text }` plus the additive fields `source` (the text of the source caption line it overlaps most), `edited` and `untranslated`, written only when set. Re-wrap and split (`fit_text`): 2 rows of 42 characters and 7 s; a longer line is split at the word boundary nearest the middle and the time is divided by character count. Edits (`set_captions`, `replace_in_captions` with `language`) rewrite the file; a re-translate puts an edited line back when the new line has the same source text and overlaps it by 50% of the shorter span (AC5), and counts `kept_edits` and `dropped_edits`.
- **Actions**: `translate_captions` is a `translate` job (held while a recording runs, like `transcribe`); event `translation.ready`; `get_captions`, `set_captions`, `replace_in_captions` and `export_captions` take `language` (files `<title> - captions.<lang>.srt|vtt`, `<title>.<lang>.txt`, edit list applied). CLI `ai translate`, `--language` on `ai captions get|set|replace` and on `export --captions`.
- **Acceptance**: AC2 (turbo rule, with a scripted transcriber), AC5 and the unit tests for re-wrap, time split and the batch retry are covered by tests with fakes; AC1 needs a real `large-v3` run and `tests/manual/AI-5.md` (not written); AC3, AC4 (glossary terms are passed to the provider as "keep as written" and enforced after the answer; tested with a scripted model), AC6 (PUB-2 caption tracks) and AC7 (Confirm with a remote provider) are not built.
- **Added Oct 27, 2026 (tested with fakes, not checked by eye)**: (1) **Undo.** `set_captions` and `replace_in_captions` with a `language` are now one manifest revision and one undo step each (`cm_library::rec_edit::apply_file`: the step keeps `translations/<lang>.json` as it was and as it became, `file_before` / `file_after`; `undo` and `redo` write it back; the replies carry `revision`, `can_undo`, `can_redo` and `capture.revised` is published). A re-translate replaces the file without a step and drops the older steps of that language (`forget_file_steps`), so undo never brings back lines of an earlier run. A history step may only name `translations/*.json`. (2) **AC4 enforcement** (`cm_ai::translate::keep_terms`, used by `translate_with_text_model`): a glossary term that is in a source line must be in its translated line exactly as the glossary writes it; a term that came back in another case is corrected in place; a lost term gives the batch one retry (with the count check); after the retry that line keeps the source text (which has the term) and is flagged `untranslated`, like a dropped line. The glossary has no per-term translation field, so every term is kept as written. Tested with a scripted text model; it applies once AI-7 is plugged in as the engine. (3) **Translate panel (V5):** the panel knows before the click whether Whisper can translate (`ModelsVm::whisper_translate`, the daemon's own `choose_translation_model` rule over the model list, which the panel reads once if nobody has) and, into English with no model that can, draws the board's model-missing state (title, which active model only transcribes, the Large v3 size, a link to the AI page) with Translate off, instead of failing into a toast. The note "Lines you edit in a translation are kept when you translate again" is shown (true: undo steps and AC5). The board's line "Or translate with your text model instead" is not drawn: the text-model engine is not plugged in.
- **Gaps**: no desktop editing of a translation (the language switcher shows the lines; edits go through `set_captions` / `replace_in_captions` with `language`), no export sheet language, no AI page rows; every undo step of a translation holds two copies of the file in the manifest history; the `large-v3-turbo` catalogue entry is pinned (SHA-256 and size from the LFS pointer file at the pinned commit, read Oct 27, 2026; `ram_mb` 2600 is an estimate, to be checked on a Mac; the file is not yet downloaded and checked on hardware); the existing `large` model is large-v3 and answers to the alias `large-v3`.

**Out of scope** — Dubbing (text to speech), translating burned-in screen text, live translation while recording (VOC-3 follow-up).

### AI-6 Transcript editor (correct mistakes and grammar)
**Priority** P1 · **Status** In progress (AI-6a built Oct 24, 2026, tested with fakes, see "AI-6a as built" below; AI-6b, the rest, is after v0.1) · **Crates** cm-ai, cm-daemon, apps/desktop · **Depends on** AI-1

**User story** — As a creator, I want to fix wrong words, names and grammar in my transcript in a proper editor, so that captions and exported text are right without re-recording or re-transcribing.

**AI-6a as built (maintainer-approved v0.1 slice, decided Oct 24, 2026; no text model and no API key involved; tested with fakes, untested by eye, glossary priming needs a real model run).** Four pieces, all offline:
- **Glossary** (`cm_ai::glossary`): the app-only setting `ai.glossary`, a list of `{ term, heard_as? }` (agents can read it through `get_settings`, not write it: `ai.*` is app-only). Used twice: the terms build Whisper's `initial_prompt` (`Transcriber::transcribe_prompted`, whisper-rs `set_initial_prompt`; Whisper keeps about 224 prompt tokens, so the prompt is capped at 160 *estimated* tokens, `PROMPT_TOKEN_BUDGET`, with a pessimistic estimate: a third of a token per ASCII character and three per other character; first terms first, a term that does not fit is skipped), and after every transcription each `heard_as` spelling in the words is replaced by the term (word by word, case-insensitive, NFC-equal, diacritics exact so `dê` never matches `đê`, edge punctuation kept, a spelling of several words merges into one word with the first start, the last end and the lowest confidence; longer spellings win; replaced text is not searched again). It runs in the `transcribe` job (`TranscribeHandler`), so the app, CLI and MCP all benefit, and the job result says `glossary_replaced`. The AI page has a Glossary section (list, add, edit, remove; no network).
- **Doubtful words** (`cm_ai::doubtful`): words below `DOUBTFUL_BELOW = 0.6` confidence are underlined (wavy, warning tone; the toolkit has no dotted underline) in the caption rows and in the field being edited. Caption lines carry only text, so the spans are found at display time by aligning each line's text with the transcript words (from the one `get_transcript` read the editor already does) that fall inside the line in time; a word the user changed no longer occurs in the line and loses its underline. The slim bar under the panel header has Previous and Next doubtful word buttons and "{n} doubtful" on the same row as Add at playhead and Save changes; Cmd/Ctrl+Alt+Up and Down do the same from the caption field. A jump selects the line, seeks the playhead to the word, puts the caret at the word and scrolls it into view.
- **Caption edits survive a re-generate** (`cm_ai::reapply`): see AI-1 above for the rule and the counts.
- **`replace_in_captions`** (MCP tool, CLI `capturemann ai captions replace`): find and replace over all caption lines with the editor's matching (`cm_ai::textmatch`, shared with the app's find), Free, one undo step, idempotent with `request_id`; the original `transcript.json` is never modified, the caption lines are the corrected text layer that feeds SRT, VTT, TXT and burned-in captions.
AI-6b (after v0.1): the full-text transcript editor, word edits with `transcript.edits` and Revert, `edit_transcript`, grammar and spelling suggestions, and AI-2. The numbered list below is the full proposal; the criteria that AI-6a meets are AC4 (the glossary, with a scripted transcriber) and part of AC6 (the old transcript stays when a run fails; the caption edits are re-applied without asking).

**Problem today** — AI-1 edits caption lines one at a time (`set_captions`); the transcript itself (`transcript.json`) cannot be corrected, so a fix does not reach the TXT export, search, AI-2 or AI-4, and a re-generate discarded all caption edits (AI-6a keeps the ones whose words are heard again).

**Description (proposed)**
- **Full-text editor** for the whole transcript, opened from the details page and the editor's Captions card: continuous text with the playhead's word highlighted, click a word to seek, and play-from-here while editing. Low-confidence words (below a threshold) are underlined so mistakes are easy to find; next/previous low-confidence jumps.
- **Word edits keep timing.** Replacing a word keeps its start and end; typing more or fewer words in a span spreads the span's time evenly; deleting words removes them from captions and text but not from the audio (cutting audio stays AI-4 / EDT-1). Corrections are stored as a layer over the Whisper output (`transcript.edits`), so the original words stay available (Revert word, Revert all) and a re-generate can offer to re-apply them where the words still match.
- **Find and replace** (case option, whole word, replace one or all) and a **personal glossary** (names, product terms) that is applied to future transcripts of any recording and offered as a prompt hint to Whisper (`initial_prompt`).
- **Grammar and spelling**: local check only (a bundled dictionary per language, flagged as underlines with suggestions); an optional pass through the AI-2 text model or the user's API key proposes fixes as a list the user accepts or rejects one by one. Nothing is rewritten without acceptance; no text leaves the machine unless that provider is chosen.
- **Speaker/section labels** are out of scope here (speaker labels are AI-8).
- **Captions follow the transcript.** Lines that were never hand-edited are rebuilt from the corrected words; lines the user edited by hand are kept and marked "differs from transcript" with an accept-transcript action.
- Every change is a revision (`user` or `agent:<name>`) and undoable; exports (SRT, VTT, TXT, burned-in) use the corrected text.

**Acceptance criteria (to refine)**
- **AC1** Given a word replaced in the editor, then the TXT, SRT, VTT export and the burned-in caption show the new word with the same timing.
- **AC2** Given a span with 2 words replaced by 4, then the 4 words share the span's time without overlap and stay inside it.
- **AC3** Given Revert all, then the transcript equals the Whisper output byte for byte.
- **AC4** Given a glossary entry, then the next transcription of a recording that says the term writes it as in the glossary in a fixture test.
- **AC5** Given network disabled, then editing, find and replace and the local spell check work.
- **AC6** Given a corrected transcript and a re-generate, then the user is asked whether to re-apply corrections, and the old transcript stays if the run fails (as AI-1).
- **AC7** Given undo after a find-and-replace-all, then every replaced word returns in one step.

**Agent interface** — MCP and CLI: `edit_transcript { capture_id, edits: [{ word_range | find, replace }] }` (Free, one undo step, idempotent with `request_id`), `get_transcript` returns the corrected text and `original` on request, `glossary` get/set (app-only for writes by agents is an open question), `suggest_transcript_fixes` (job, returns suggestions, applies none). CLI `capturemann ai transcript edit|replace|glossary`.

**Scope note (Oct 24, 2026):** the grammar and AI-suggestion parts depend on AI-2's text model and move after v0.1 with it; the spell check should use the operating system's checker behind a trait (no bundled dictionaries); a possible v0.1 slice (AI-6a) is the glossary (primes Whisper and corrects after), low-confidence underlines in the caption editor and keeping caption edits on re-generate, pending the maintainer's decision. Note that since the caption editor (R3c) the caption fixes already reach SRT, VTT, TXT and the burned-in captions, so "Problem today" above applies only to `transcript.json` itself, AI-4 and re-generate.

**Open questions** — Where the glossary lives (global settings vs per library); whether grammar suggestions ship with AI-2 or earlier with only the local dictionary; threshold for low-confidence underlining.

**Out of scope** — Speaker diarization (AI-8), translation (AI-5), editing the audio itself.

**Test notes** — Unit tests for time redistribution and the correction layer, golden SRT/VTT/TXT after edits, glossary prompt test with a scripted transcriber, UI by hand in `tests/manual/AI-TRANSCRIPT-EDIT.md`.

### AI-7 Text model provider
**Priority** P1 (targeted for the next release; it is the backend AI-2, AI-5 and AI-9 need) · **Status** In progress (**built-in engine, Oct 27, 2026: backend, actions, MCP tools, CLI and AI page built and tested with fakes; the helper build, the model catalogue pins and every run with a real `llama-server` and a real model are not done, see "Built-in engine" below**; backend built and tested with fakes, see "As built, AI-7" below; the AI page section is built and tested with fakes and offers None and Built in only; release 0.2.0 drops the user-chosen local server and Remote and Anthropic stay unavailable, maintainer decision Oct 27, 2026: see "As built, AI-7" below) · **Crates** cm-ai, cm-daemon, cm-auth, apps/desktop · **Depends on** NFR-9, NFR-10, DESIGN §5.11

**User story** — As a user, I want CaptureMann to use a text model running on my own Mac, so that summaries, translations and reports work offline and nothing is sent anywhere unless I decide.

**Description**
- **Provider kinds (release 0.2.0, maintainer decision Oct 27, 2026):** `none` and **Built in** (provider `embedded`); the page shows no None / Built in control, only the model list (see "Built-in engine"). The app ships llama.cpp's `llama-server` (MIT) as a **helper program** inside the bundle, like FFmpeg, and never links llama.cpp into the app (whisper.cpp and llama.cpp both embed ggml; two copies in one process clash). The app starts it on `127.0.0.1` when the first text request arrives and talks to it with an OpenAI-compatible HTTP client that only ever connects to loopback. The models are GGUF files downloaded on request, the way Whisper models are (see "Built-in engine" below). There is no user-configurable server address, no Remote and no Anthropic provider.
- **Later (backlog):** a user-chosen local server through an OpenAI-compatible URL (Ollama, LM Studio, with presets, detection and a model picker), and a provider with the user's own key. Both are marked *later*; neither is part of 0.2.0, and no UI, setting, tool or flag for them exists.
- **Local vs remote** is decided by the URL host: loopback (`127.0.0.1`, `::1`, `localhost`) is local; anything else is remote, even on the LAN, and is refused. The code paths for a remote provider (first-use notice, Confirm plan) are dormant and unreachable in 0.2.0: settings cannot select a remote provider.
- **Settings (app-only, `ai.text.*`):** `provider` (`none` default or **`embedded`**; the daemon treats anything else, `local` included, as `none`, see `TextModelConfig::from_settings`), `model`, **`embedded_model`** (a built-in model id; empty: the one chosen with `select_text_model`; an id the catalogue no longer has, such as `text-8gb` written by an earlier version, reads as no model selected: provider `none`, nothing crashes), `context_tokens` (the resolved built-in model's; default 8,192), `timeout_s` (default 300). There is no `base_url` setting. Agents can read them through `get_text_model` (never the key) and cannot write them.
- **Test button** sends a short prompt and shows the reply time, the model name and whether structured output works.
- **Structured output.** Callers ask for JSON that matches a schema (`response_format: { type: "json_schema" }` to the built-in engine); the reply is validated, and one retry with the validation error is allowed before `job_failed` with `reason: "invalid_model_output"`.
- **Long input.** When the prompt would exceed 60% of `context_tokens`, callers split the transcript into chunks at speaker turns or sentence ends (about 40% of the context each, 5% overlap), process chunks, then merge (map-reduce). Shared helper in `cm-ai`.
- **No network** when the provider is `none`; the built-in engine only talks to loopback.

**Acceptance criteria**
- **AC1** Given the AI page, then the built-in models are listed (Gemma 4 E2B marked Recommended, Qwen3.5 4B, Qwen3.5 2B) with their size, memory and licence and no None / Built in control; pressing Use on a downloaded model selects it and turns the engine on, after which Test shows a reply time. A model whose `ram_mb` does not fit the Mac's memory shows a warning. The page offers no other provider.
- **AC2** Given provider `none`, then AI-5 (non-English targets) and AI-9 fail with `invalid_input` and `data.reason = "no_text_model"`, and the app shows where to set one up.
- **AC3** *Withdrawn for 0.2.0* (maintainer decision Oct 27, 2026: no remote provider). A settings file that names a remote provider is read as `none`, so nothing is ever sent. The Confirm plan returns with the remote provider (*later*).
- **AC4** Given a model reply that fails the schema twice, then the job fails with `invalid_model_output` and the previous result (if any) is kept.
- **AC5** Given a 2-hour transcript and `context_tokens` 8,192, then the request is chunked and no single request exceeds the context.
- **AC6** Given the built-in provider, then a network monitor sees traffic only to loopback during an AI-9 job.

**Edge cases and errors** — Engine not answering → `job_failed` with `reason: "text_model_unreachable"` and "Open the AI page and check the built-in text model"; model not loaded or out of memory → the server's message is passed through; timeout → `job_failed` (`timeout`).

**Agent interface** — `get_text_model` → `{ provider, model, local, context_tokens, structured_output }` (Free, read-only; no key). `test_text_model` → `{ ok, latency_ms, model }` (Free; uses only the configured provider). Settings are app-only. CLI `capturemann ai text-model [test]`.

**Out of scope** — Linking llama.cpp into the app (it is a helper program), a user-chosen server, a Remote or Anthropic provider (all *later*), fine-tuning, embeddings and semantic search (P2). Model weights are downloaded only on request (see "Built-in engine").

**Test notes** — A scripted OpenAI-compatible server in tests (schema success, schema failure, timeout, unreachable); loopback-only check; manual script `tests/manual/AI-7.md` with the built-in engine.

**Built-in engine (provider `embedded`; maintainer decision Oct 27, 2026)**

*Why a helper program.* llama.cpp and whisper.cpp both embed ggml; linking both into the app risks symbol clashes, and a model that crashes or runs out of memory should not take the app with it. The helper is built by `make llama` (`packaging/llama/build-macos.sh`: pinned release, static, Metal, no Python, no libcurl or OpenSSL, self-check of the licence and the linked libraries; output `packaging/llama/out/{llama-server,BUILD-INFO.txt,LICENSES/}`), bundled and signed by `make bundle` (`CM_NO_LLAMA=1` skips, `CM_LLAMA_BUNDLE` names a binary, `make bundle-release` requires it) and found at run time in this order: `CM_LLAMA_SERVER` (a file or a folder), next to the executable (`Contents/MacOS` in the bundle), `PATH`. Its licence (MIT) and those of the small libraries it vendors travel in `Contents/Resources/Llama/`; `NOTICE` names it.

*Models.* `crates/cm-ai/data/text_models.json` has the shape and the rules of `models.json`: id, label, hint, file, URL pinned to a commit, SHA-256, size in bytes, `ram_mb`, `aliases`, `pending_pin`, plus `recommended` (true on exactly one offered entry: the default, shown as Recommended on every Mac), `license` (Apache-2.0 or MIT only) and `context_tokens` (the context the engine starts it with). An entry with `pending_pin` is hidden from `list_text_models` and every action on it is refused; **the three shipped entries (maintainer decision Oct 27, 2026: reports need no reasoning and no big models) are `gemma-4-e2b` (Gemma 4 E2B, the default and recommended on every Mac), `qwen3.5-4b` (Qwen3.5 4B, optional, best for translation into other languages; the file `Qwen3.5-4B-Q4_K_M.gguf` of earlier versions stays recognised under this id) and `qwen3.5-2b` (Qwen3.5 2B, the smallest, for Macs with little free memory); pins and sizes are in `docs/research/text-model-pins-2026-10-27.md` (checksums read from the Hugging Face pointer files, not yet confirmed by a download)**. `<config dir>/ai/text/catalog.json` or `CAPTUREMANN_TEXT_CATALOG` replaces the list. The files live in `<config dir>/ai/text/models/`, the chosen one in `ai/text/state.json`. The downloader, its progress, resume (`Range`), size and checksum verification and the removal are the Whisper store's (`cm_ai::model::ModelStore`): `cm_ai::text_model::store::TextModelStore` wraps one rooted at `ai/text`. Nothing is downloaded unless a user or an agent action asks.

*Actions (Free unless noted; MCP tool and CLI of the same name).* `list_text_models` (`capturemann ai text-models`): `{ models: [{ id, label, size_mb, ram_mb, recommended, license, context_tokens, hint, installed, active, path }], active, dir }`. `download_text_model { model }` (`ai text-models download <id> [--wait]`, **Confirm**: the dialog names the model, its size, its licence and the folder): a `text_model_download` job, resumable and cancellable with `cancel_job`. `select_text_model { model }` (`ai text-models use <id>`): the downloaded model that runs; it sets `ai.text.provider` = `embedded` and `ai.text.embedded_model` = the id (the same as the Use button, so the CLI and agents behave like the app) and loads nothing. `remove_text_model { model }` (`ai text-models rm <id>`, **Confirm**): `busy` while it is being downloaded or a job is using it; an idle engine is stopped first so the file is not in use; removing the model that is in use sets `ai.text.provider` = `none`. Turning the engine off without removing the file is "Don't use a model" on the AI page (it writes `ai.text.provider` = `none`); agents cannot write that app-only setting. Events: `model.download.progress` and `model.changed` of a text model carry `"kind": "text"` (the speech models' do not carry `kind`). `get_text_model` adds `embedded_model` and `engine` (`{ state: stopped | starting | running | failed, model, port, in_flight, restarts, helper, reason, error, idle_stop_s }`); with the built-in provider `model` is the resolved downloaded model (empty while none is downloaded) and `context_tokens` its catalogue context.

*Engine rules.* One helper at most. It starts lazily on the first text request (never at app start), with `--host 127.0.0.1 --port <free port> --model <gguf> --alias <id> --ctx-size N --n-gpu-layers 999 --parallel 1 --no-webui` and `GET /health` is waited for (up to 3 minutes); later requests reuse it. After 10 minutes without a request it is stopped; it is stopped on app exit and by `remove_text_model`, and it ends by itself when the app process is gone (a watchdog in the shell that starts it, even after a kill -9). A helper found dead is started again once for the request that finds it (the request is retried once); a start that fails is reported, not retried in a loop. Asking for another model while a request runs is refused; otherwise the engine restarts with it. **Memory guard:** a model whose `ram_mb` exceeds the memory that can be used now (free, inactive and speculative pages) is refused before anything starts. **Loopback only:** the base URL is chosen by the engine, is always `http://127.0.0.1:<port>/v1`, and the client is a `local` provider, so the AI-7 loopback check runs on every request; the helper gets no URL, has no libcurl or OpenSSL, and `llama-server` has no telemetry (NFR-9). Settings, tools and events never contain a recording's text.

*Failure codes.* A text request made while the built-in provider is chosen fails with the shared codes: no downloaded model is `invalid_input` with `data.reason = "no_text_model"` (checked before a job is queued, and again when it runs); the helper missing from the app is `job_failed` with `reason: "engine_missing"` ("run `make llama`" in a developer build, "reinstall CaptureMann" in an app bundle); the helper that would not start, died while loading, did not answer in time or died twice is `engine_failed`; a model that does not fit in memory is `not_enough_memory`. `test_text_model` returns them as `ok: false` with the `reason` and `message`.

*Acceptance criteria (built-in engine)*
- **AC7** Given provider `embedded` and a downloaded model, when nothing has asked for text yet, then no helper is running (`engine.state` is `stopped`); when `test_text_model` or a report or translation job runs, then the helper starts once, the request goes to `127.0.0.1` only, and a second request reuses it.
- **AC8** Given the helper idle for the idle time, then it is stopped and the next request starts it again; it is not stopped while a request runs.
- **AC9** Given a helper that died, then the next request starts it once; given one that cannot start (missing, out of memory, did not load), then the request fails with `engine_missing`, `not_enough_memory` or `engine_failed` and nothing is left running.
- **AC10** Given provider `embedded` and no downloaded model, then AI-5 (non-English targets) and AI-9 fail with `invalid_input` / `data.reason = "no_text_model"` and the Report tab says a text model is needed and links to the AI page (and offers the recommended download).
- **AC11** Given a model download interrupted halfway, then the next call resumes it, and a file that fails its SHA-256 or size is deleted and never used. A `pending_pin` entry cannot be listed, downloaded, selected or removed.
- **AC12** Given the app quits (or is killed), then no `llama-server` is left running.

### AI-8 Speaker labels (who spoke when)
**Priority** P1 (targeted for the next release, after spike S7 passes) · **Status** In progress (Oct 26, 2026: everything that does not depend on the model is built and tested with fakes; the model part waits for spike S7; the Speakers lane and tab in the app are not built) · **Crates** cm-ai, cm-daemon, apps/desktop · **Depends on** AI-1, VOC-1, DESIGN §5.5, §5.11

**User story** — As an interviewer with one laptop on the table, I want the transcript to show who said what, so that interview notes and meeting minutes credit the right person, even when everyone speaks into the same microphone.

**Description**
- **Speaker diarization from voices, not devices.** Speakers are found from the audio itself (voice activity → segmentation → speaker embeddings → clustering), so one microphone with several people works. Track-based shortcuts are optional: the setting "My microphone only hears me (headset)" (per recording, default off) labels the whole mic track as the user and diarizes only the system track.
- **Input.** The mix of the recording's audio tracks (mic denoised + system), at 16 kHz mono for the models; times are session time (pauses removed as in AI-1).
- **Speakers.** Labelled "Speaker 1 … N" in order of first speech. An optional hint `num_speakers` (exact) or `min_speakers`/`max_speakers` improves clustering; the In-the-room preset asks "How many people?" (optional) in the sheet.
- **Words get speakers.** Each transcript word is assigned the speaker active at its midpoint; overlapping speech goes to the louder speaker and the line is marked as overlap. Stored as `diarization.json` (segments `{ start, end, speaker }`, model, created); the manifest holds `speakers: [{ id, name }]`.
- **Naming and fixing.** Rename a speaker once (Speaker 2 → "Linh") and it changes everywhere; merge two speakers; reassign a line or a selection to another speaker. Each is one undoable revision.
- **Display and exports.** The transcript panel and caption editor show the speaker name at each turn. TXT and Markdown exports write "Name: text" per turn with timestamps; VTT uses voice tags (`<v Linh>`); SRT can prefix "LINH:" (switch, off by default). AI-9 reports use the names.
- **Models.** Downloaded on request on the AI page, like Whisper models (explicit download, checksum, size notice, import from file). Runtime: ONNX models through `ort` (shared with CAM-5) unless S7 picks otherwise. Only models whose licence allows redistribution and use in an Apache-2.0 app (MIT, Apache-2.0, BSD, or CC-BY with attribution in `THIRD_PARTY_LICENSES.md` and on the AI page). Candidates and the decision rule are in the plan.
- **Privacy.** Speaker embeddings (voiceprints) exist only in memory during the job and are never written to disk; recognising the same person across recordings is out of scope.

**Acceptance criteria** (thresholds are initial targets, calibrated in S7 and revised in place with a dated note)
- **AC1** Given a 10-minute two-person interview recorded on a laptop's built-in microphone in a quiet room, then at least 90% of transcript words get the correct speaker.
- **AC2** Given a 30-minute four-person meeting fixture recorded on one microphone, then diarization error rate is ≤ 20% (no collar, overlap scored) and the job finishes in ≤ 3 minutes on an M-series Mac with 16 GB.
- **AC3** Given `num_speakers: 2`, then exactly two speakers are produced.
- **AC4** Given the user renames Speaker 2 to "Linh", then the transcript panel, TXT export and the next AI-9 report all say "Linh", and one undo restores "Speaker 2".
- **AC5** Given a merge of Speaker 3 into Speaker 1, then no word remains labelled Speaker 3, and undo restores both.
- **AC6** Given the network is off and the model installed, then AI-8 works end to end, and no voiceprint file exists in the bundle or the config folder after the job.
- **AC7** Given "My microphone only hears me" on a call recording, then every word from the mic track is labelled with the user's name (setting `profile.display_name`, default "Me") and only the system track is diarized.

**Edge cases and errors** — No model installed → `invalid_input` with `data.reason = "no_speaker_model"`; no transcript → diarization still runs and the transcript gets speakers when it arrives; one speaker detected → all words labelled "Speaker 1" with a note; very short recording (< 10 s) → skipped with a note.

**Agent interface** — `diarize { capture_id, num_speakers?, min_speakers?, max_speakers?, headset?, request_id? }` → `{ job_id }` → `{ speakers, segments }` (Free). `set_speakers { capture_id, rename?: { "<id>": "<name>" }, merge?: [{ from, into }], assign?: [{ start, end, speaker }], request_id? }` → `{ revision, speakers }` (Free, one revision). `get_transcript` adds `speaker` to each word and `speakers` to the result (additive). Events `speakers.ready`. CLI `capturemann ai speakers <id> [--num 2]`, `capturemann ai speakers rename <id> 2 Linh`.

**As built (Oct 26, 2026, tested with fakes; the real engine and models were added Oct 27, 2026, see "Real engine" below)** — Built and tested with a scripted `Diarizer`: `cm_ai::speakers` (the `Diarizer` trait, `ScriptedDiarizer`, `NoSpeakerModel`; numbering and naming "Speaker 1..N" by first speech; word assignment at the midpoint with the louder speaker winning an overlap, which marks the word `overlap`; headset mode with `profile.display_name`, default "Me"; rename, merge and reassign; `diarization.json` `{ version, model, created, headset, note, segments }`; the TXT, Markdown, VTT (`<v Name>`) and SRT (`NAME:`) writers; `find_voiceprint_files`, the AC6 check), the `diarize` job and `set_speakers` action (MCP tools and CLI `ai speakers [<id>] | rename | merge | assign | list`), the event `speakers.ready` (`{ capture_id, model, speakers, segments, note, headset }`), and `get_transcript` with `speaker` (and `overlap`) per word and `speakers`. Stored data: `diarization.json` is the raw result of the last run and is never edited; the manifest keys `speakers` (`[{ id, name }]`) and `speaker_segments` (the working segments after merges and reassignments) are what `set_speakers` changes, as one revision (`edit_history` step with `extra_before` / `extra_after`) that undo and redo restore; a new `diarize` run replaces them without a revision and drops the undo steps of the older run. Words get their speaker when read, so a transcript made later (or again) still gets speakers and `transcript.json` is never changed. `export_captions` gains `format: "md"` and `speaker_names` (SRT only, default off); VTT, TXT and Markdown name the speakers whenever the recording has them. `diarize` also takes `headset` (default false). `profile.display_name` is a normal setting: agents can read and write it. **AI page part (board V8, Oct 26, 2026; tested with fakes; not checked by eye):** the Speaker labels section shows the speaker model card (licence and size before any download; with the empty catalogue of `voice::speaker_catalogue` it says "Speaker model not available yet" until S7 decides, and no model or URL is invented), the switch "Find speakers after each transcript" (`ai.auto_speakers`, app-only, default off, disabled until a model is installed) and "Your name in transcripts" (`profile.display_name`, default "Me"). The speaker model download itself is not wired (no daemon action yet). **Not built (as of Oct 26; the first two items were done Oct 27, see below):** the real speaker model and runtime (production wired `NoSpeakerModel`), the model download and licence display, `ai.auto_speakers`, the Speakers lane and tab, the "Speaker names" export switch and the headset shortcut in the app, the AI-9 use of the names, AC1 to AC3 (accuracy, speed, hint effect), and `tests/manual/AI-8.md`. AC4 to AC7 are covered by `crates/cm-daemon/tests/ai_speakers.rs` and `crates/cm-ai/src/speakers/tests.rs`, but AC6 and AC7 against the real model and a real call recording still need S7.

**Real engine (Oct 27, 2026; spike S7 on macOS arm64; tested with a scripted engine, run once against the real models on one 11-minute recording, accuracy NOT measured)** — `cm_ai::speaker_engine`: `SherpaDiarizer` (a `Diarizer`) runs sherpa-onnx 2.0.1 offline diarization (pyannote segmentation-3.0, then CAM++ English voice embeddings, then clustering), linked statically from the pinned libraries of `make sherpa` (`packaging/sherpa`; the Rust bindings are vendored in `vendor/` with a build script that only links; cargo feature `sherpa`, default on; a build without it answers that it has no speaker engine). `ready()` and every run look for the two model files in the model store, so a model installed while the app is open works at once; without both, `diarize` still answers `invalid_input` with `data.reason = "no_speaker_model"`. **The count is passed to the engine:** `num_speakers` is the exact cluster count (spike S7: the default threshold found 29 speakers on a 2 to 3 person recording). Without it the engine runs with a high threshold (`AUTO_THRESHOLD` 1.2, tuned on one recording only), folds speakers who hold under 8 s or 4 % of the speech into the nearest voice in time, and if the result is outside `min_speakers` / `max_speakers` (default maximum 8) runs once more with that exact count; this automatic count is a best-effort suggestion and the user can merge speakers. `min_speakers` / `max_speakers` need that second pass, so they cost a second run. Clean-up (`tidy_turns`): a turn under 0.5 s whose neighbours (within 0.5 s) are one other speaker goes to that speaker, and same-speaker turns closer than 0.5 s are joined; overlapping turns of different speakers stay and the louder speaker wins at word assignment, as before. Speakers are numbered by first speech (`diarize_audio`). The engine has one blocking call, so progress is 0 then 1 and a cancel is noticed before and after it. Embeddings stay inside the call: nothing is written but `diarization.json` (AC6). **Models** are rows of the model store of kind `speaker` (`crates/cm-ai/data/speaker_models.json`, pinned by SHA-256 and size): `speaker-segmentation` (pyannote segmentation-3.0 `model.onnx`, MIT, 5,992,913 bytes) and `speaker-embedding` (CAM++ English VoxCeleb, Apache-2.0, 29,596,978 bytes, from the sherpa-onnx release). They are listed, downloaded, imported and removed with the existing `list_models`, `download_model`, `import_model` and `remove_model` (rows carry `kind`, `license` and, for the segmentation file, `import_only`); an import must be exactly the pinned file; speaker rows are never the active speech model and `transcribe` / `select_model` refuse them. **The segmentation model is import-only for now:** it is published only inside a `.tar.bz2`, the app does not unpack archives, and no direct URL of the extracted `model.onnx` is known, so `download_model` refuses it (`invalid_input`, naming `import_model`) and the AI page offers Import from file with the instruction to unpack the archive. Maintainer to-do: host `model.onnx` at a fixed URL, put it in `url` and remove `import_only`. **The app:** the AI page "Speaker labels" card shows both files (licence, size, state, Download / Import / Resume / Cancel / Remove, progress) and the "Find speakers after each transcript" switch (still off by default and disabled until both are installed); the Speakers tab "Find speakers" works when both are installed and otherwise says what is missing. "How many people?" now starts on a sensible count instead of "Not sure": 2 for the in-the-room preset (a conversation across a table), 1 for a voice note, 3 otherwise; the user's choice (including Not sure) wins, and the row is also shown after a run so "Find again" can use another count. Real-model run (`cargo test -p cm-ai --test real_diarize -- --ignored`, release build, Apple M4 Pro, one 675.7 s English recording, 4 threads): 2 speakers 101 turns in 34.7 s (RTF 0.051), 3 speakers 114 turns in 34.5 s, automatic 2 speakers 101 turns in 35.0 s, peak memory footprint 283 to 293 MB (maximum resident set 302 to 320 MB). This is speed and memory only: there is no ground truth, so AC1 to AC3 (accuracy, the 30-minute four-person fixture on a 16 GB Mac) are not checked; AC6 holds by construction and by the AC6 file check; AC7 against a real call recording is unrun. Windows and Intel Macs have no libraries yet. Covered by `crates/cm-ai/src/speaker_engine/tests.rs`, `crates/cm-daemon/tests/ai_engine.rs` (`ai_8_speaker_models_...`) and `apps/desktop/src/ai/models.rs` tests; manual script `tests/manual/AI-8.md` still to be run.

**Bundled models (maintainer decision, Oct 27, 2026; tested with fakes and stand-in files, the packaging script run offline from the cache, the app not launched)** — The two speaker models **ship inside the app**, so speaker labels need no setup (no download, no import, no network): `packaging/sherpa/fetch-models.sh` (run by `make sherpa`) fetches the pinned files (segmentation `model.onnx` out of `sherpa-onnx-pyannote-segmentation-3-0.tar.bz2`, unpacked with the system `tar` at build time only; CAM++ from the sherpa-onnx release), checks every SHA-256 and writes `packaging/sherpa/out/models/` with the licence files; `packaging/macos/bundle.sh` copies the two files and `LICENSES/` into `Contents/Resources/Models/speaker/` (about 36 MB, data files, nothing to sign; `CM_NO_SPEAKER_MODELS=1` skips, `CM_SPEAKER_MODELS_BUNDLE` points at another folder); `make bundle-release` (`CM_REQUIRE_SPEAKER_MODELS=1`) and `verify-release.sh` require them. **Lookup:** `ModelStore` treats a speaker file as installed when it is in the user's models folder (an imported or downloaded copy **wins**, which keeps the CLI/MCP `import_model` usable for development) or in the bundled folder (`CM_SPEAKER_MODELS_DIR`, else `<executable dir>/../Resources/Models/speaker`). A bundled file is checked against the pinned size and SHA-256 once per process; one that does not match is refused (`diarize` fails with an `internal` error saying the app is damaged, not `no_speaker_model`). `list_models` rows of bundled files carry `installed: true` and `bundled: true`; `remove_model` on a file that exists only in the app is refused (`invalid_input`, `bundled`), and when a user copy exists it deletes only that copy. **AI page:** the speaker model card, its two file rows and their Download / Import buttons are gone (nothing to offer); only a build without the models shows one row, "Speaker model: Not available in this build", and the Speakers tab then says so (without an Open AI page button); with the models present "Find speakers" works at once and the switch "Find speakers after each transcript" is enabled. ### AI-9 Summaries and reports (meeting minutes, interview notes, 1:1 notes and more)
**Priority** P1 (targeted for the release after AI-7 ships) · **Status** In progress (backend built and tested with fakes, see "As built, AI-9" below; the Report tab and the manual run with a real local model are not built) · **Crates** cm-ai, cm-daemon, apps/desktop · **Depends on** AI-1, AI-7, AI-8 (optional, for names), VOC-1 (markers), DESIGN §5.5

**User story** — As someone who just finished a meeting, interview or product presentation, I want a structured report made from the recording, so that decisions, action items and key answers are written down with links to the exact moment, without typing notes during the conversation.

**Description**
- **Templates** (built in, versioned data in `crates/cm-ai/data/reports/`, each a section list plus a JSON schema with `additionalProperties: false`):

| Template | Sections |
| --- | --- |
| Summary | Summary (≤ 150 words), key points |
| Meeting minutes | Summary, attendees, topics with key points, decisions, action items (owner, task, due if said), open questions, marked moments |
| One-on-one notes | Updates, wins, concerns, feedback given and received, agreed actions, follow-ups for next time |
| Interview notes | Role and candidate (from context), questions and answers (pairs, in order), evidence per competency (quotes), candidate's questions, follow-ups |
| Product presentation recap | Product and audience, features shown, questions asked, concerns raised, next steps |
| Lecture notes | Key points, definitions, examples, 5 review questions with answers |

- **Inputs.** The transcript (edited caption lines win over raw words), speaker names (AI-8) when present, markers (VOC-1), and optional context the user types in the Report panel: title, attendees, agenda; for interviews the role and a competency list. Output language: the transcript's by default, or any language the model handles.
- **Every item cites the recording.** Each decision, action item, answer and quote carries one or more `at` times (session seconds) that must fall inside a transcript line; items whose citations don't match the transcript are dropped and counted (`dropped_uncited`). Owners and names may only be attendees, speaker names or words found in the transcript; otherwise the owner is "Unassigned". Clicking a citation seeks the editor.
- **Interview notes do not judge.** The schema has no score, rating, ranking or hire/no-hire field, and the prompt forbids inferring personal traits (age, accent, emotion, personality). The report collects evidence; the decision stays with the interviewer. The template's panel says: "Notes only — CaptureMann doesn't score candidates. Using AI to assess candidates is regulated in some places." (for example the EU AI Act treats AI used in recruitment as high-risk).
- **Storage.** `reports/<id>.json` (template, template version, model, provider, created, context, content) and `reports/<id>.md` rendered from it; several reports per capture; each create, edit or delete is one revision. A report can be edited as Markdown in the Report panel (marked edited). Regenerate replaces it only on success (like AI-1).
- **Exports.** Markdown file, plain text, Copy (Markdown or rich text); a report can be uploaded with the recording to a destination (STO-5 adds `report` to "what to upload").
- **Long recordings** use the AI-7 chunking (notes per chunk, then a merge pass with the same schema).

**Acceptance criteria**
- **AC1** Given a 30-minute meeting fixture with speaker names and the recommended built-in model on an M-series 16 GB Mac, when generating Meeting minutes, then the report is ready in ≤ 5 minutes, validates against its schema, and every action item has an owner from the attendees/speakers or "Unassigned".
- **AC2** Given any report, then every cited `at` time falls inside a transcript line, and clicking it seeks the editor to that time.
- **AC3** Given a scripted model that invents an action item with a time outside the transcript, then that item is dropped and `dropped_uncited` is 1.
- **AC4** Given the Interview notes template, then the stored JSON contains no score, rating, ranking or recommendation field (schema check), and the panel shows the notes-only line.
- **AC5** Given a 3-hour transcript and `context_tokens` 8,192, then the report is produced through chunking and its sections cover the whole recording (citations in the first and last 10% of the timeline exist when the transcript has content there).
- **AC6** Given the user edits the report and then undoes, then the previous text returns; given Regenerate fails, then the old report stays.
- **AC7** Given output language Vietnamese for an English meeting, then all section text is Vietnamese and quotes stay in the original language with their times.
- **AC8** Given a remote provider, then generating a report from an agent asks for confirmation (AI-7.AC3) and the app shows the one-time notice before the first send.

**Edge cases and errors** — No transcript → `not_found` with the way to transcribe; no text model → `no_text_model`; transcript shorter than 30 words → "Too little speech for a report"; model refuses or returns empty sections → those sections say "Nothing found" rather than invented content.

**Agent interface** — `list_report_templates` → `[{ id, name, sections, context_fields }]` (Free). `generate_report { capture_id, template, language?, context?: { title?, attendees?, agenda?, role?, competencies? }, request_id? }` → `{ job_id }` → `{ report_id, dropped_uncited }` (Free with a local provider; **Confirm** with a remote one). `get_report { capture_id, report_id? }` → JSON and Markdown (Free). `export_report { capture_id, report_id, format: "md"|"txt", out_dir? }` → path (Free). `delete_report` (Free, undoable). Events `report.ready`, `report.failed`. Resource `capturemann://capture/{id}/reports`. CLI `capturemann ai report <id> --template minutes [--lang vi]`, `capturemann ai report get|export|templates`.

**Out of scope** — Custom user templates (P2), DOCX/PDF export (P2), sending reports by email or posting to Slack/Notion (agents can do this with their own tools), calendar attendee import.

**Test notes** — Scripted text model for schema, citation-drop and chunking tests; golden Markdown rendering; a small quality review set (3 meetings, 2 interviews, 1 lecture in English and Vietnamese) scored by hand in `verification/`; manual script `tests/manual/AI-9.md`. **Report view, ticks and the offer after stop (Oct 27, 2026, tested with fakes, not checked by eye):** (1) *Ticks.* A task can be ticked: action `check_report_item { capture_id, report_id, section, index, checked? }` (Free, MCP tool of the same name, CLI `ai report check`). Only the task sections (`cm_ai::report::CHECKABLE_SECTIONS`: `action_items`, `agreed_actions`, `follow_ups`, `next_steps`) take ticks; the tick is `"<section>:<index>"` in `Report.checked` of `reports/<id>.json` (absent when empty), written as a new version of the report and one revision `check_report_item` (the index entry is unchanged), so `undo` and `redo` restore it and the live file follows; the same tick twice is `changed: false` with no revision; a regenerate starts with none ticked and an edit as Markdown keeps them. Covered by `crates/cm-daemon/tests/ai_reports.rs` (`check_report_item_is_stored_and_undoable`). **As built, AI-9 (Stage 5 backend, Oct 26, 2026, tested with fakes)** — `cm_ai::report`: six templates as versioned data in `crates/cm-ai/data/reports/*.json` (`summary`, `minutes`, `one_on_one`, `interview`, `product_recap`, `lecture`; each has `sections`, `context_fields`, `suggested_for` and the JSON `schema` of the model's reply, `additionalProperties: false` at every object level; `Template::forbidden_judging_fields` is the schema check that finds no score, rating, rank, recommendation or hire field in Interview notes, which carries the `notes_only` line). The reply is `{ <section>: [item] }`; every item has `at` (seconds). After each model call the reply is validated against the schema and then checked against the transcript: an `at` outside every caption line (1 s tolerance) is removed, an item left with none is dropped and counted (`dropped_uncited`; only the attendee list may have no citation), an owner that is not an attendee, a speaker name or words of the transcript becomes "Unassigned" (`reassigned_names`; an attendee with such a name is dropped). "Marked moments" is built from `manifest.markers` (pauses added back) and "Role and candidate" from the context, never by the model; an empty section renders "Nothing found". The transcript sent is the caption lines (edited lines win) as `[seconds] Speaker: text`, with speaker names (AI-8), markers and the context; the output language is an instruction (quotes stay as spoken). A transcript that needs chunking (AI-7: more than 60 % of `ai.text.context_tokens`) is cut with `map_reduce` into notes per chunk with the same schema, then merged in groups that fit a chunk, level by level; a 3-hour transcript at 8,192 tokens runs through chunks and merges (tested with a scripted model; every prompt stays under the context). Storage: `reports/<id>.json` and `reports/<id>.md` (the edited text when edited), every version kept in `reports/versions/<id>.v<N>.json`, and the manifest key `reports` (`[{ id, v, template, created, edited }]`) is the index that create, regenerate, edit and delete change as ONE revision (`apply_extra`); undo and redo restore the index and the live files are made to match (so `undo` after `edit_report` brings the earlier text back). Regenerate (`generate_report` with `report_id`) writes only after a success, so a failed run keeps the old report and publishes `report.failed`. Actions (Free): `list_report_templates`, `generate_report` (a `report` job; result `{ report_id, dropped_uncited, reassigned_names, chunks, language, model, revision }`; events `report.ready` and `report.failed`), `get_report` (one report, or without an id the list and the newest in full), `export_report` (`md` or `txt`, never overwrites), `delete_report` and `edit_report` (added for the Report panel's edit-as-Markdown; marks the report `edited`), MCP tools of the same names (the `capturemann://capture/{id}/reports` resource serves `get_report`), CLI `capturemann ai report <id> --template minutes [--lang vi] [--title --attendee --agenda --role --competency] [--report ID] [--wait]`, `ai report templates|get|export|delete|edit`.
