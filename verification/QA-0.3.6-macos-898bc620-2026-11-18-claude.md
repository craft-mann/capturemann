# QA 0.3.6, macOS, on the dev bundle built from 898bc620 (PARTIAL)

- **Date:** 2026-11-18. **Who:** Claude (QA agent). **Machine:** Apple Silicon Mac, built-in display plus one external display, macOS 26.x, screen unlocked.
- **Build:** the existing `target/bundle/CaptureMann-dev.app` was older than HEAD (it still reported 0.3.5), so I ran `make bundle-dev` of HEAD 898bc620 (version 0.3.6, bundle id `dev.capturemann.app.dev`); `codesign --verify --deep --strict` passed. Debug `capturemann`, `cm-daemon`, `cm-mcp`, `cm-regress` and the `cm-ai` examples were built with `cargo build`.
- **Isolation:** every app run used its own library, config dir, `CAPTUREMANN_SECRETS=file` and a socket under `/tmp` (main instance `/tmp/cmqa36.sock`, a second instance with `--demo-quick-capture` / `--demo-launcher` on `/tmp/cmqa36d2.sock`). `CM_DEMO_CAPTURABLE=1` (the existing debug switch) was set on those instances only so that the floating windows (panel, bar, toast, Confirm card, launcher) could be captured by window id; without it they are hidden from capture by design. `~/Applications/CaptureMann-dev.app` and `/Applications/CaptureMann.app` were not touched or stopped. Everything under `/tmp/cmqa36` was deleted at the end.
- **Method:** `capturemann` CLI, `cm-mcp` over stdio, `cm-regress`, keyboard events posted to my own app's process (`CGEventPostToPid`: 1 2 3, Tab, Up, Down, Left, Right, P, Return, Esc, Cmd+,), captures of my own windows by window id, `AppleScript` for the process's window list. Synthetic audio only: macOS `say` (voice Linh, Vietnamese) turned into clips by `short_guard_probe make`, transcribed with the ggml `medium` model that is already installed on this Mac (symlinked into the isolated config, nothing downloaded).
- **Not done (no consent):** microphone, camera, system-audio recording, any real recording; I did not press Record in the panel or on the bar, and I declined a recording Confirm card.
- **Skipped for a technical reason:** pointer clicks (system-wide click injection was refused earlier, clicks posted to the process do not reach gpui controls), so nothing that needs a mouse click was driven. Global hotkeys (Option+Shift+C and the others) are not triggered by events posted to a process, so I opened the panel with `cm-desktop --demo-quick-capture` and the launcher with `--demo-launcher`. The panel has no accessibility-tree children (System Events shows an empty window), so accessible names could not be read from outside.
- **Privacy / incident (please read):** (1) Once I ran `capturemann library list` in a shell where my isolation variables were not set. It reached the maintainer's running app on the default socket and printed three rows (titles) of the maintainer's real library; I did not copy them anywhere. That call also auto-started a headless `target/debug/cm-daemon` (16:08:49) that opened `~/Movies/CaptureMann` (index and jobs databases, read only use, no capture, no write command was sent). I found it at the end, stopped it with `kill`, and nothing else was done against that library. (2) A `ps` listing I ran to look for leftover processes printed command lines of unrelated processes (one contains a bearer token); I did not store or copy them. (3) Display screenshots made for the preset and panel tests contain the maintainer's other windows; they were written only to my temporary library, never opened, and deleted. No such picture is in `verification/QA-0.3.6-shots/`.
- **Pictures** (all my own windows, by id): `verification/QA-0.3.6-shots/`: `macos-panel-default.png`, `-video`, `-audio`, `-picker`, `-tab4-up`, `-delay-5s`, `-copy-off-display`, `macos-after-bar.png`, `macos-toast-edit-undo.png`, `macos-confirm-qa-rec.png`, `macos-confirm-longshot.png`, `macos-panel-vi-screenshot.png`, `-vi-video`, `macos-main-vi-dock.png`, `macos-panel-pseudo-screenshot.png`, `-pseudo-audio`, `macos-main-pseudo-dock.png`, `macos-launcher-quick.png`, `macos-launcher-preset.png`, `macos-library-dock.png`.
