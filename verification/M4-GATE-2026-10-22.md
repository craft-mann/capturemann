## Findings (bugs and mismatches; none fixed in this run)

**F1 (FIXED Oct 22, 2026: every export starts at `live_at`; untouched 12 s fixture 11.8 s, 60 s fixture 59.8 s on both renderers). The default in-point differs by 0.19 s between the two export paths.**
- *Repro:* `make_fixture --secs 60 --no-pause`; `capturemann export ID --wait` gives a **60.0 s** file starting at the screen's first frame (0.39 s). After any stored edit, e.g. `capturemann edit cut ID 10-15` then `restore`, `capturemann export` gives **59.81 s** starting at `live_at` (0.58 s). The CLI says "the export is now 59.81 s" after `restore` or `split` while the file is 60.0 s. The `source` preset (and any list with no real edit) also gives 60.0 s; the platform presets give 59.8 s.
- *Expected:* `specs/01-technical-design.md` (One clock): "the editor's default in-point start at `live_at`". The edited path follows it; the untouched interim path does not.
- *Decision for the maintainer:* make the untouched path start at `live_at` too (then 59.81 s everywhere), or document 60.0 s as the interim exporter's behaviour.

**F2 (FIXED Oct 22, 2026, same day). Every edited export leaves a raw audio temp file in the bundle's `exports/` folder** (`<title> - <preset>.<ext>.<pid>-<n>.mix.part`, stereo float PCM, about 23 MB per minute; 7.6 MB for a 20 s clip). 61 of them (hundreds of MB) after this run's ~70 exports.
- *Repro:* any export through the compositor path (e.g. `edit trim ID --start 2 --end 8`, `export ID --wait`), then `ls "<bundle>/exports"`.
- *Expected:* the temp file is removed when the export finishes or fails. This is a disk-space hazard for users (a one-hour export would leave about 1.4 GB behind per export).

**F3. EDT-4.AC3: follow-cursor zoom can leave the cursor on the frame edge** in about 5 % of sampled frames (72 of 76 at 2.5x over 40 s; reframe follow kept it in 100 %). Repro and the 23.0 s frame: see [EDT-4 report](EDT-4-2026-10-22-claude.md). Detection was a pixel difference between two exports, so a person should confirm.

**F4 (FIXED Oct 22, 2026). Background image errors come late.** `edit background --kind image --value /nonexistent.png` succeeds; the export then fails with `job_failed` (exit 6). The script and the spec's wording expect `invalid_input` when it is set. A JPEG is accepted and drawn although the notes said PNG only. (Scripts updated to describe what happens.)

**F5 (FIXED Oct 22, 2026). `make_fixture` does not mark the screen track as cursor-free**, so on a fixture the cursor is neither drawn nor editable, contrary to the EDT-4 script. A real "record cursor separately" recording has `tracks.screen.cursor = false`. Test-copy workaround used here: `python3 -c "import json,sys;p=sys.argv[1];m=json.load(open(p));m['tracks']['screen']['cursor']=False;json.dump(m,open(p,'w'),indent=1)" "<library>/<title>.cmrec/manifest.json"`.

**Smaller notes:** the 640x360 to 1080x1920 upscale prints no quality warning on the CLI; the click ripple lasts between 0.7 and 1.4 s (script says about half a second); the bubble clears the vertical right safe area by 2 px; the default 9:16 bubble sits at the right, not "bottom third centred" (script wording); `capture get` is screenshot-only (EDT-1 step 10 corrected).

## Maintainer checklist: what only you can do

Setup once (all three variables in every terminal, from `tests/manual/M4-GATE.md`):
`export CAPTUREMANN_LIBRARY=/tmp/cm-m4-library CAPTUREMANN_CONFIG_DIR=/tmp/cm-m4-config CAPTUREMANN_SOCKET=/tmp/cm-m4.sock`, `cargo run -p cm-daemon --example make_fixture -- --library $CAPTUREMANN_LIBRARY` (12 s) and the 60 s copy (`--title "Fixture 60s" --secs 60 --no-pause`), then (the F5 workaround is no longer needed: fixtures are stored with the cursor separate)  `cargo run -p cm-desktop` (or the signed bundle with the same variables).

1. **PLAY-1, all 11 steps** (headphones, low volume): flash and beep together (limit about 50 ms), no freeze at the 1 s pause, loop with `L`, scrubbing, frame step, edits while playing, mute and gain, no audio device, 30 s on the 60 s copy. Report CPU while playing and the output device.
2. **EDT-1 step 2 and 3/5 by eye:** `I`/`O`/`S`/`Delete`/`R`, hatched cut, Cmd+Z, playing across the cut with no click or freeze.
3. **EDT-2 by ear:** the 300 Hz tone sounds the same pitch inside a 1.5x, 2x and 0.5x segment, no clicks at the segment edges, 4x is silent unless Keep audio; the 2x badge and the digit counting faster.
4. **EDT-3 in the window:** the four presets, the "Lens Violet" name (maintainer decision), padding/radius/shadow controls, the preview matching an exported frame, gradient banding at normal size. Screenshots of steps 3, 5, 6.
5. **CAM-3 in the window:** the Camera card (layouts, corner, size, shape, ring, mirror, smooth move), a layout per split segment, and screenshots of steps 2, 5, 7. Dragging the bubble is not built.
6. **EDT-4 in the window:** cursor size/smoothing/click effect, a zoom lane, `Z`, Follow cursor on a zoom (is the cursor ever on the edge? see F3), the ripple duration, and "hide when idle" (needs a real short recording with the pointer resting).
7. **EDT-5 in the window:** the reframe card, drag/glide in Follow mode (watch the file at 0.25 speed), and whether the export sheet warns about upscaling a 640x360 source.
8. **EXP-2 in real players:** open the `youtube-1080p` file in QuickTime Player, Safari and Chrome next to the editor preview: the same colours (no orange/teal shift); the GIF loops in Chrome; the WebM plays with sound in Chrome and Firefox; the editor's export list disables `youtube-4k` on a 1080p recording with the hint.

## Fixes after this run (Oct 22, 2026)

* **F2:** the success path disarmed the cleanup guard for every scratch file; it now forgets only
  the renamed `.part`, so the mixed-audio (and GIF stage) scratch files are deleted on success,
  failure and cancel. The stale-file sweep also reads the maintainer pid of `*.mix.part` and
  `*.mid.part` names. Test: `exp4_a_finished_mixed_export_leaves_no_scratch_files`.
* **F4:** `set_background` with `kind: image` checks the file exists and decodes (PNG or JPEG,
  absolute or relative to the recording's folder) and returns `invalid_input` naming the path;
  nothing is stored. JPEG support is now explicit (`image` feature `jpeg` in `cm-media` and
  `cm-daemon`) instead of a side effect of feature unification. Test:
  `edt3_image_background_is_checked_when_it_is_set`.
* **F5:** `make_fixture` writes `tracks.screen.cursor = false` when it writes a cursor log, as a
  real "record cursor separately" recording does. Side effect to know: such a fixture is no longer
  "untouched" for the exporter, so it takes the edit-list path (in-point 0.58 s, 11.81 s) instead
  of the interim `quick` path (12.0 s); `--no-cursor` keeps the `quick` path. This is the same
  in-point question as finding 1, which is fixed (maintainer chose `live_at` everywhere): now both
  renderers give 11.8 s for the 12 s fixture.
