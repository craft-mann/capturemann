# macOS app bundle

`bundle.sh` builds the release binaries and assembles `target/bundle/CaptureMann.app`
(`make bundle`, `make run-bundle`). Why: macOS attaches Screen Recording (and later Camera,
Microphone, Accessibility, Input Monitoring) to the *responsible app*. A bare
`./target/release/cm-desktop` started from a terminal is attributed to that terminal, so captures
break when you launch it from another host (Terminal, VS Code, ...). Inside the bundle the
permission belongs to "CaptureMann" (`dev.capturemann.app`) no matter who launched it.

## Layout

```
CaptureMann.app/Contents/
  Info.plist            from packaging/macos/Info.plist (@BUNDLE_ID@, @VERSION@ filled in)
  PkgInfo
  MacOS/cm-desktop      CFBundleExecutable
  MacOS/cm-overlay      capture overlay helper; cm-desktop looks next to its own executable
  MacOS/cm-mcp          MCP server; Settings > Agents & CLI finds it next to cm-desktop
  MacOS/capturemann     the CLI (cm-cli's binary name)
  MacOS/ffmpeg, ffprobe   only with CM_FFMPEG_BUNDLE (LGPL build, signed with the app's identity)
  Resources/AppIcon.icns  design/brand/app-icon/AppIcon.icns (kit icon, not duplicated)
  Resources/LICENSE, NOTICE, THIRD_PARTY_LICENSES.md
```

`THIRD_PARTY_LICENSES.md` (repo root) is generated by `make licenses`
(`packaging/macos/gen-third-party.sh`): every crate linked into the four binaries (normal
dependencies, both macOS targets) plus the four font families (OFL); identical license texts are
printed once. It is committed; regenerate it when `Cargo.lock` changes (CI regenerates it before
bundling). The MPL-2.0 crate (option-ext) is listed in it with a source note; `NOTICE` repeats the
source-availability statement. `bundle.sh` fails if one of the three files is missing.

Tray icons are embedded in the binary (`include_bytes!`), so nothing else is copied. Binaries are
not stripped (release profile keeps debuginfo), so backtraces stay readable. `LSUIElement` is not
set: the app has a Studio window, a launcher and a tray icon, so it appears in the Dock
(`lsappinfo` reports it as a "Foreground" app). `--background` (login item) only skips the Studio
window; the Dock icon stays.

## Environment

| Variable | Meaning |
| --- | --- |
| `CM_BUNDLE_ID` | Bundle identifier, default `dev.capturemann.app`. The owner may change it before the first release; it is the TCC identity, so changing it later makes everyone re-grant permissions. |
| `CM_SIGN_IDENTITY` | codesign identity (certificate name or SHA-1). When unset, `bundle.sh` uses "CaptureMann Local Dev" if `security find-identity -v -p codesigning` lists it, else ad-hoc (`-`). It prints the mode it chose and never creates or changes keychain items. |
| `CM_HARDENED=1` | Add `--options runtime --timestamp` (only useful with a real identity; required for notarization). |
| `CM_SKIP_BUILD=1` | Reuse `target/release` instead of running `cargo build --release`. |
| `CM_BUILD_NUMBER` | `CFBundleVersion`, default the workspace version. |

## Signing and permission grants

Every binary is signed with a fixed identifier (`<id>`, `<id>.overlay`, `<id>.cli`, `<id>.mcp`),
helpers first, then the bundle. The check is `codesign --verify --deep --strict`.

* **Symptom of a dropped grant.** "permission is not granted" in a toast, "Screen Recording
  permission is missing" in the Record sheet, or the same line as a banner in the library; Settings
  > Permissions shows Screen Recording as "Not granted". **Remedy:** switch the CaptureMann entry
  off and on in System Settings > Privacy & Security > Screen Recording (or remove it and add the
  new `.app`), then quit and reopen CaptureMann. The permanent fix is the stable identity below.
* **Ad-hoc (used when no "CaptureMann Local Dev" identity exists).** The designated requirement is `cdhash H"..."`, the hash of the exact
  build. Rebuilding with unchanged inputs gave an identical cdhash in testing, but any code
  change produces a new one. macOS ties a TCC grant to the designated requirement, so after a
  rebuild with changes the old Screen Recording entry no longer matches: capture fails with
  "permission not granted" and you must switch the CaptureMann entry off and on (or remove it
  with `-` and add the new `.app`), then restart the app. This is expected macOS behavior, not
  a bug here. Not verified end to end: no TCC state was touched while writing this.
* **Stable identity (recommended for daily development).** With a certificate the designated
  requirement becomes `identifier "<id>" and certificate leaf = H"<cert hash>"`, which does not
  change between rebuilds, so the grant survives. Create a local one once:

  ```
  packaging/macos/create-dev-identity.sh            # asks twice before changing your keychain
  security find-identity -p codesigning             # note the name
  CM_SIGN_IDENTITY="CaptureMann Local Dev" make bundle
  ```

  The script is never run by `bundle.sh`; once the identity exists, `bundle.sh` finds it by itself
  (a read-only `security find-identity -v -p codesigning` lookup) when
  `CM_SIGN_IDENTITY` is unset, and prints "signing mode: local dev identity found in the keychain".
  An identity listed as untrusted (not shown by `-v`) is treated as missing. If you skip its trust question (or the identity is
  listed as untrusted), open Keychain Access > login > Certificates > "CaptureMann Local Dev" >
  Get Info > Trust > Code Signing: Always Trust. The first signing may prompt for keychain
  access; choose Always Allow (the script does not run `security set-key-partition-list`, which would need your login password). The PKCS#12 password goes to openssl on stdin; `security import -P` needs it on argv, visible in `ps` for a moment.

## One-time steps for the user

1. `make run-bundle` (or `make bundle`, then open `target/bundle/CaptureMann.app`).
2. Trigger a screenshot. macOS asks for Screen Recording for "CaptureMann", or open System
   Settings > Privacy & Security > Screen Recording and enable CaptureMann.
3. Quit and reopen CaptureMann (macOS requires a restart after the grant).

Quit any `./target/release/cm-desktop` first, or give the bundle its own
`CAPTUREMANN_SOCKET` / `CAPTUREMANN_LIBRARY` / `CAPTUREMANN_CONFIG_DIR`, otherwise the two
instances fight over the daemon socket.

## Entitlements

`CaptureMann.entitlements` is applied to `cm-desktop` and to the bundle on every signing (also
without `CM_HARDENED`, so dev builds exercise the same path):

* `com.apple.security.device.camera` and `com.apple.security.device.audio-input`: under the
  hardened runtime (required for notarization) the `NSCameraUsageDescription` /
  `NSMicrophoneUsageDescription` strings alone are not enough; without these a notarized build
  cannot open the webcam or the microphone.
* Screen Recording needs no entitlement (TCC only); the app is not sandboxed.
* Not added: `com.apple.security.cs.disable-library-validation`. Any dylib or helper that ships
  later (FFmpeg, ffprobe) must be signed with the same identity; `bundle.sh` does that for
  `CM_FFMPEG_BUNDLE`.
* Helpers (`cm-overlay`, `cm-mcp`, `capturemann`) open no devices and get none.

Check: `codesign -d --entitlements - target/bundle/CaptureMann.app`.

## FFmpeg (NFR-12, NFR-15)

The app ships its own LGPL FFmpeg so a user installs nothing: `make ffmpeg` builds `ffmpeg` and
`ffprobe` from pinned upstream sources (`packaging/ffmpeg/build-macos.sh`, see
`packaging/ffmpeg/README.md`), and `make bundle` copies them into `Contents/MacOS` next to the app's
own executables, signs them with the app's identity (same hardened-runtime options as the rest) and
puts `SOURCE-OFFER.txt`, `BUILD-INFO.txt` and the licence texts (FFmpeg LGPL-2.1, libvpx, libopus)
into `Contents/Resources/FFmpeg/`.

* Without `CM_FFMPEG_BUNDLE`, `make bundle` bundles `packaging/ffmpeg/out/ffmpeg` when it exists;
  `CM_NO_FFMPEG=1` makes a recording-only app. `make bundle-release` (`CM_REQUIRE_FFMPEG=1`) fails
  unless an LGPL FFmpeg and its licence files are bundled: use it for anything you distribute.
* `bundle.sh` refuses a build whose configuration has `--enable-gpl`, `--enable-nonfree`,
  `libx264`, `libx265` or `libfdk-aac` (unless `CM_ALLOW_GPL_FFMPEG=1`, for a local-only bundle).
* `cm-media` looks next to its own executable before `PATH`, so a Homebrew FFmpeg never changes how
  an installed app behaves; `CM_FFMPEG` still overrides it. If the copy inside the app is missing or
  cannot start, the error says the app is damaged and to reinstall it (not "brew install").
* arm64 only, macOS 13 or later. A universal (arm64 + x86_64) binary needs a second build with
  `nasm` and `lipo`; Windows needs its own build (see `packaging/ffmpeg/README.md`).

```
CM_SIGN_IDENTITY="Developer ID Application: NAME (TEAMID)" CM_HARDENED=1 packaging/macos/bundle.sh
ditto -c -k --keepParent target/bundle/CaptureMann.app target/bundle/CaptureMann.zip

xcrun stapler staple target/bundle/CaptureMann.app
spctl --assess --type execute -vv target/bundle/CaptureMann.app
```

(`notarytool store-credentials AC_NOTARY` creates the profile once.) The entitlements above are
already passed by `bundle.sh`; the hardened runtime itself was only verified with a local identity
(`flags=0x10000(runtime)`), never submitted to Apple. Ship a `.dmg` after stapling.

## CI

`.github/workflows/ci.yml`: fmt/clippy/test on macOS and Windows with FFmpeg installed (the gated
export tests no longer print SKIPPED), `bundle-macos` on pushes to main (licenses, ad-hoc bundle,
entitlements dump, zip uploaded as a 3-day artifact), and `cargo deny check licenses bans sources
advisories`. The seven ignored `unmaintained` advisories in `deny.toml` are all transitive via
gpui/usvg/zbus; revisit them on every gpui upgrade.

## A grant that stays "not granted"

A permission granted while the app was signed ad hoc is stored against that build's code requirement. After the app is signed with "CaptureMann Local Dev" the switch in System Settings still looks on, but macOS refuses (`/usr/bin/log show --last 1h --predicate 'subsystem == "com.apple.TCC" AND eventMessage CONTAINS[c] "capturemann"'` shows `Failed to match existing code requirement for subject dev.capturemann.app`). Remove the CaptureMann entry with the minus button in Privacy & Security, quit and reopen the app, and grant it again. (Do not run `tccutil` against the bundle id of your daily copy.)
